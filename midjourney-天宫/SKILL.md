# Midjourney 东方天界巨构导演

## 核心原则

从文字建立原创画面，并让随机变化服从同一视觉语法：

> 一座连续且延伸出画框的中国古建巨构 + 一个大面积空明天域 + 一套清楚的主辅构图 + 一个真实落位的极小人物 + 一组有物理站位的电影镜头 + 冷环境中的少量方向性暖光。

随机只改变未锁定的空间组合，不能随机掉以上关系。用户明确条件优先；未指定项先进入选项问卷，不直接套用默认。朝代名称只作为幻想建筑的视觉线索，不声称考据复原。

“巨构压迫感、震撼、宏大”只描述尺度关系，不自动切换为暗色、冷峻或低曝光模式。默认只在用户选择“默认/推荐”或明确要求跳过询问时使用；随机只作用于用户标记为随机的模块。

## 交互入口

每次使用本 Skill，先完整读取[缺项问卷](references/interactive-questionnaire.md)。在生成提示词前解析六个模块：已指定项直接锁定，只对未指定项提供完整固定选项并等待用户选择。对话内可视化能力可用时必须优先提供可点击按钮选择器；只有不可用时才回退为完整文本选项。除非六个模块均已确定，或用户明确说“全部默认、全部随机、其余推荐、不要问、直接生成”等跳过口令，否则本轮不能生成最终提示词。

## 六维路由

每次创建、改写或批量编写提示词，按顺序读取并应用：

1. [风格](references/style.md)
2. [画幅](references/aspect-ratio.md)
3. [构图](references/composition.md)
4. [镜头](references/camera.md)
5. [光线色彩模式](references/light-and-color.md)
6. [元素](references/elements.md)

优先级始终是：`用户明确要求 > 系列锁定 > 本 Skill 默认 > 随机选择`。不同维度冲突时，保留用户条件，并重选兼容项；只有用户条件本身互相矛盾时才询问。

## 默认候选

只有用户选择默认/推荐或跳过询问时，才应用以下内容：

- 风格：电影级写实东方神话环境 CG，庄严、静谧、超现实但结构可信。
- 画幅：`16:9`。
- 构图：留白构图为主，三分构图为辅；巨构位于一侧，另一侧保留空明天域。
- 镜头：相机位于建筑内部或可行走边缘，中等广角、低畸变、深景深；近景巨构被裁切并延伸出画框。
- 光色：明亮仙境；天青冷环境、朱红或深木建筑、左上方暖金清晨斜光、正常曝光。
- 元素：一座连续中国宫廷巨构、平整云海、一名性别不强调的成年背影仙者。其他奇观不自动加入；摆放方式在用户选择推荐/默认或跳过询问时使用 `F5-1`，按九宫格参考兼容随机。

## 工作流程

1. 按缺项问卷进入 `ASK`、`WAIT`、`ASK_REMAINING` 或 `GENERATE`。问卷回合只提问并停止，不能提前给提示词。
2. 进入 `GENERATE` 后，建立“六维锁定卡”，记录用户指定项、选择项、默认项和受控随机项。
3. 先锁定连续巨构、开放天域、主辅构图、人物尺度、镜头物理站位及整批色光，再从元素库中选择有限的从属元素，并按 `F5` 摆放模式确定每个可见元素的位置。
4. 批量任务整批固定风格、画幅、主建筑体系或朝代、色彩家族、光向、曝光，以及人物数量、性别策略和尺度。用户要求构图随机时，逐张登记主辅构图，兼容主构图用尽前不重复。每张至少改变镜头所在空间、观看方向、巨构方向、开放区位置四项中的三项；此要求针对相邻画面，兼容镜头用尽前不重复。只有用户明确要求相应锁定维度随图变化时才解除锁定。
5. 按以下顺序写 Midjourney 正向提示：
   `风格身份 → 画幅行为 → 主辅构图关系 → 镜头物理关系 → 主巨构与朝代线索 → 开放天域 → 人物、选中元素及其画面位置 → 光线色彩 → 材质与气氛`。
6. 参数必须位于提示词末尾。默认使用 `--ar 16:9 --raw --s 450 --c 8`；画幅替换为用户选择，单次必须给出具体数值，不能输出数值范围。用户指定参数时服从用户；不自动写死模型版本。
7. `--no` 只列当前最危险的简单对象词，例如 `neon, cyberpunk, skyscraper, text, logo, watermark`。先用正向关系控制画面，不用长串负面词代替构图。

## 标准输出

### 问卷回合

优先只输出对话内按钮选择器：显示已锁定摘要，并在每个缺失模块内完整显示全部固定选项；单选、多选、自定义摆放和自动回传按缺项问卷执行。若按钮选择器不可用，输出完整文本选项与回复示例。输出后停止，不生成提示词。

### 生成回合

六个模块确定后，除非用户要求简洁，只输出：

1. `六维锁定卡`：风格、画幅、构图、镜头、光线色彩、元素。
2. `Midjourney 提示词`：一个可直接复制的代码块。除非用户明确要求“中文提示词”，代码块内必须使用英文视觉描述并在末尾放置参数；中文只用于代码块外的锁定卡与解释。
3. `变化说明`：仅用于随机或批量任务，说明整批锁定项和逐张变化项。

用户要求“只要提示词”且同时表示直接生成或已经提供全部模块时，不输出解释。仅说“只要提示词”本身视为跳过询问。没有可用的 Midjourney 提交工具时，只交付提示词，不声称已经生成图片。

## 交付审计

- 第一眼是否是一座连续巨构，而非许多等大的独立亭阁？
- 是否同时存在局部高密度结构和约占画面 `40%–60%` 的内容承载空气，例如天空、云海、云峡、水庭或深渊？
- 是否明确一个主构图和最多一个辅助构图，并写成可见关系而非标签堆叠？
- 若存在未指定模块，是否先完整显示缺失模块的全部固定选项并停止，而不是直接生成？
- 可用对话内可视化能力时，是否使用按钮选择器，并完整显示缺失模块内的全部固定选项？
- 相机是否有真实站位、观看方向与被裁切的近景构件？
- 人物是否仅占画面高度约 `0.15%–0.45%`、面部不可辨，并站在可承载平面上？随机摆放时是否允许人物落在画面中段，而非总在底部？
- 是否只加入用户指定或元素预算允许的内容，没有自动堆满天环、浮山、瀑布、天梯和体积光？
- 是否已经确定 `F5` 摆放方式，并将每个选中元素的位置写成与构图、镜头和物理承载兼容的可见关系？
- 色光是否统一、暖色覆盖克制、暗部可读、云层不过曝？
- “冷青柱光”是否落在承重柱材质关系上，而不是蓝色柱状体积光？
- 参数是否全部位于末尾，且 `--ar` 使用整数比例？

任一核心项失败时先修提示词，再交付。

# 东方天界电影巨构导演

## 核心原则

从文字建立原创画面，不依赖源图：

> 局部高密度的连续东方古建巨构 + 大面积开放天域 + 延伸出画框的超尺度结构 + 极小尺度标记 + 冷底暖光。

随机只改变观看关系和场景组合，不能随机掉这套视觉语法。
用户未指定色彩、天气、时辰、亮度或曝光时，默认使用“明亮仙境”：朱红暖白天青 + 清晨晴光 + 左上方暖金斜射光 + 明亮正常曝光。随机场景只随机空间骨架，不随机掉这套明亮色光；用户明确选择其他色光模式，或明确要求随机色彩、天气、时辰或氛围时才改变。

## 永久视觉规则

无论用户只写一句话、要求随机，还是指定完整场景，都必须自动补齐以下规则：

- 主体是一座连续、可进入、可承重的东方建筑巨构，不是若干独立宫殿、亭台或模型的拼贴。
- 复杂度集中在顶部、单侧或结构转换处；另一侧必须给天空、云谷、水庭或远景留下大面积安静负空间。
- 至少一组深檐、承重柱、墙体、桥廊或宫基被画框裁切并继续延伸到画框之外，以证明空间规模超过画面。
- 相机必须位于建筑内部、构件旁或真实可行走边缘；具体机位与镜头展开遵循 `references/camera-language.md`。
- 人物、坐骑、古松、栏杆等只作为极小尺度标记，并真实依附在平台、桥面、水庭、廊道或台阶等承载平面上。
- 云海以平整、连续的水平雾带组织，远景逐级降低饱和度、细节和反差；不得堆成散乱棉花云。
- 环境保持冷静，方向性暖光只作局部结构标记；同一批次锁定色彩家族、光向、色温与曝光基线。
- 保持电影级 CG、真实建筑厚度、稳定结构和清楚大轮廓；禁止霓虹、UI、文字、水印与无依据的能量特效。

用户的短口令只负责指定变量；未写出的部分由这些永久规则和参考文件自动补齐。

## 色光模式选择

按以下优先级决定：用户明确指定 > 用户从下表选择 > 明亮仙境默认。用户没有选择时直接使用默认，不为色光额外追问。

| 模式 | 色彩与光线 | 适用倾向 |
|---|---|---|
| 明亮仙境（默认） | 朱红暖白天青 + 清晨晴光 | 清透、明亮、神圣、层次清楚 |
| 雾白仙境 | 雾白暗木 + 云隙光 | 空灵、柔和、珍珠灰水汽 |
| 苍青日出 | 青黑铜金 + 日出 | 冷峻、庄严、局部暖金 |
| 暮蓝朱砂 | 蓝灰朱砂 + 暮蓝 | 幽远、克制、稀疏灯火 |
| 暗色史诗 | 青黑铜金 + 落日 | 压迫、深沉、暗红金边；仅在用户明确选择暗色时使用 |
| 冷青柱光（显式可选） | 冷青、铁蓝灰、雾白 + 承重柱局部暗铜暖反光 | 整体不提亮；暖光只擦亮主要承重柱朝光面与浮雕凸起 |

用户只说“随机场景”不等于随机色光；只有“随机色调”“每组不同氛围”等明确表达才从非默认模式中抽取。无论采用哪种模式，同一批或同一组内部仍锁定统一光向、色温、曝光、天空清澈度和雾层亮度。

“冷青柱光”只在用户明确点名时启用。“柱光”中的“柱”指承重柱，不是柱状光束：不得生成冷青色体积光柱、传送门光束或大面积舞台光。深檐、开口、云海、水庭与人物维持冷色和原有曝光；暖色只集中在承重柱朝光面、浮雕凸起和局部弧面，表现暗铜、旧金与柔和琥珀反光，不能把整座建筑染黄或整体提亮。

## 纯文本边界

- 不把原始图片、截图、缩略图或其他视觉资产放入 skill。
- 不在提示词中写来源图片、图片编号、文件名或文件路径。
- 不复刻特定作品的精确布局、人物、纹样、文字、标志或水印。
- 只使用本 skill 及其 `references/` 下按路由读取的文字参考文件；不继承其他导演 skill 的规则或资料。
- 实际生成的图片保存到用户指定位置；未指定时保存到当前可写工作区，绝不保存进 skill 目录。

## 必读路由

1. 每次导演、写提示词或生图前，完整读取[视觉语法](references/visual-grammar.md)。
2. 每次完整读取[镜头语言](references/camera-language.md)，把镜头口令或用户的物理机位要求展开成完整镜头句。
3. 用户说“随机”“来一张”“多张”“批量生成”或未锁定构图时，完整读取[随机场景矩阵](references/random-scene-matrix.md)。
4. 输出最终提示词或调用生图工具前，完整读取[提示词契约](references/prompt-contract.md)。

## 工作流程

1. 提取用户固定条件：主体、人物或坐骑、自然锚点、数量、画幅、亮度、色彩家族、光线路线、光向、曝光、镜头口令或物理机位和排除项。用户指定的内容不可被随机替换；未指定色光时锁定“明亮仙境”默认。
2. 锁定永久视觉规则。批量任务在此处额外锁定整批统一的色彩家族、光线路线、光向、色温和曝光。
3. 按镜头语言解析镜头，优先级为：用户明确物理条件 > 命名镜头口令 > 与结构兼容的自动选择。
4. 从随机矩阵选择兼容的主构图原型、巨构形态、天域、叙事与自然锚点。若没有原型兼容用户镜头，不得强塞原型；保留镜头硬约束并重建兼容骨架。只有用户条件本身互相矛盾时才询问。
5. 普通随机任务保持“明亮仙境”默认；只有用户明确要求随机色调时，单张可抽取一次色光，批量任务只在整批或每个用户定义的组开始时抽取一次，组内复用，不逐张重抽。
6. 先写场景蓝图，再按提示词契约装配正向提示词；负面边界只负责阻止常见偏移。
7. 用户只要提示词时，交付蓝图和最终提示词。用户要图片时，使用可用的位图生成工具从零生成；画幅未指定时采用宽银幕 16:9。
8. 生成后进行缩略图审计。若主轮廓、空间、镜头或色彩语法失效，只针对失效项修订，不把所有细节一起重写。

## 批量差异

批量生成时，在兼容选项耗尽前不重复主构图原型和镜头口令，并至少改变镜头所在空间、观看方向、巨构方向、开放天域中的三项。不能只换人物、服装、颜色或装饰。所有图片共享同一视觉不变量，并默认共享同一色彩家族、光线路线、光向、色温和曝光。只有用户明确要求色彩、天气、时辰或氛围也随图变化时，才逐张重抽这些变量。

## 完成审计

- 第一眼是否先读到一个连续巨构关系，而不是许多大小相近的小亭阁？
- 相机是否有明确物理站位、观看方向与近景裁切，而不是悬空地图视角？
- 建筑复杂度是否集中在局部，同时保留足够大的天空、云海、深渊或水庭？
- 是否至少有一个屋檐、柱阵、墙体或宫基自然延伸出画框？
- 人物、坐骑、栏杆或树木是否作为极小尺度标记并真实落位？
- 是否符合已锁定色彩家族的冷暖组织：冷色环境保持成立，暖色覆盖范围受控，避免电光蓝、翠绿、通体亮金或全局橙色？
- 若启用冷青柱光，暖光是否只落在承重柱并形成局部暗铜反光，而非体积光柱或全局增亮？
- 云是否呈平整云海、横向雾带或水汽层，而不是遍布棉花云？
- 是否静谧、庄严、超现实但稳定，无恐怖化、霓虹化、UI、字幕、Logo或水印？
- 批量任务中，各图是否保持同一色彩家族、光线路线、光向、色温和曝光，而差异主要来自空间骨架？

任一核心项失败时不交付为合格结果。

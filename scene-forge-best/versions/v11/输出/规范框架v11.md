- 文件名：`规范框架v11.md`
- 版本：11.0
- 日期：2026-10-29
- 状态：V11 开放创作版；文档检查通过并交付，实际模型调用与出图未执行。
- 基线：V10；意图优先、参考与必需分离、库外主体及条件属性，配套工作台V15。保留十维、地域、独立负面、模型分支、历史示例和三个画面模块。
- 定位：用于设计、生成、检查和迭代文生图提示词的通用基础标准。
- 项目范围：作为新项目独立制定；赛博朋克是首个应用示例，不限定后续题材。

## 1. 目标与适用范围

本规范将简短创作需求转化为具有明确意图、视觉逻辑、设计差异和可检查约束的画面方案，再转换成适合目标图像模型的提示词。

主要目标：

1. 保持题材与美术方向的一致性。
2. 让人物、载具、建筑、设施、环境等元素具有可解释的设计和变化。
3. 避免反复生成同一构图、同一轮廓、同一人物或同一套题材符号。
4. 明确画幅、镜头、尺度、裁切和交付要求。
5. 支持不同题材、画面类型和图像模型。
6. 支持独立探索、系列创作和局部定稿。

适用任务包括角色、载具、道具、建筑、环境、叙事插画、海报、封面、产品展示、图案与抽象图像。

本规范主要约束提示词设计过程。它不保证图像模型逐项遵从，也不把结构化字段当作所有模型均支持的直接输入接口。

## 2. 基本概念与规则等级

### 2.1 基本概念

| 概念 | 定义 | 示例 |
|---|---|---|
| 题材 | 世界背景、文化、技术或超自然规则及内容范围 | 赛博朋克、历史幻想 |
| 地域 | 本次画面的地理、文化语境或指定范围的地域美术参考 | 真实地区、城市、虚构地域或明确融合；不是用户所在地 |
| 美术方向 | 形状、色彩、材料、照明和细节组织方式 | 冷灰工业设计、暖色手工质感 |
| 表现媒介 | 图像采用的视觉表达形式 | 摄影、水彩、平面插画、三维渲染 |
| 核心概念 | 一张图最主要的设定或表达 | 停运车站被改造成维修市场 |
| 元素 | 画面中的对象、设施、生物、空间或现象 | 轨道、人物、投影、雾 |
| 关系 | 元素之间的空间、行为、功能或光影联系 | 人物操作终端；轨道连接站台 |
| 画面设计稿 | 供创作者与提示词助手使用的完整结构化设计 | 单图设计卡 |
| 最终提示词 | 从设计稿中筛选并适配给目标模型的描述 | 主体、关系、构图、光色等画面信息 |
| 模型适配 | 按平台与版本调整措辞、参数和参考使用方式 | 将排除要求转换为受支持的表达 |

题材、美术、媒介、单图内容必须分别记录。不能默认一个题材只能使用一种配色、一种媒介或一种天气。

### 2.2 规则等级

| 等级 | 含义 | 处理方式 |
|---|---|---|
| 必须满足 | 失败即不符合当前任务 | 出图后逐项检查 |
| 优先满足 | 对效果重要，但允许有限调整 | 与更高优先级要求冲突时调整 |
| 允许变化 | 明确开放的设计空间 | 可主动探索并记录变化 |
| 不适用 | 当前任务不需要该项 | 省略，不强行补齐 |

本文件中的“必须”是工作流程或验收要求，不表示模型能自动保证执行。

不可兼容的必须项不能静默舍弃，应明确冲突并请求取舍。一般偏好冲突时，优先考虑用户明确需求、任务可用性、主体可读性、美术偏好，再考虑装饰细节。

### 2.3 示例、选项与默认值的适用范围

- 示例是一次具体设计选择，用于展示如何应用规范；示例中的题材、画幅、镜头、人物数量、位置、配色和材质不自动成为其他任务的默认设置。
- 字段表中列出的多个值是可选范围，不要求全部采用，也不表示必须选第一个。
- 只有明确写出“默认”及其适用条件的条款才构成默认规则；用户明确要求优先，普通设计选择按当前任务补齐。
- 用户没有指定某项时，应依据本次画面类型、主体和约束重新设计，不能因第 13 节出现过某设置就直接继承。
- 引用或复制示例局部内容时，应保留“仅用于本例”的标识。用户明确要求沿用某个示例时，再按指定范围复用。

```text
通用文生图提示词设计规范
├─ 01 通用规则：需求理解、设计顺序、约束、创新与去重
├─ 02 题材设定：世界规则、时代文化、元素库、题材边界
├─ 03 美术设定：媒介、形状、色彩、材料、照明、细节密度
```

通用规则保持稳定；题材包和美术方案可替换；单图设计随任务变化；模型适配随平台与版本维护。

## 4. 输入规范与任务判断

### 4.0 用户输入：十个维度与独立负面提示词

用户通过十个主面板选择条件，另设独立负面提示词。自然语言同样有效；除自动预填值外无需填满全部面板，大致说明也可留空。仅表达感觉、画面特点或模糊念头同样可以开始创作，不要求先选择题材或元素。以下是当前默认入口，不要求用户填写内部长表。地域作为可选补充项，独立于题材和表现风格，不增加必填主面板；可以写在下方地域行或用自然语言说明。

```text
题材：
元素：
视觉偏好：自动设计
镜头：自动设计
风格与复杂度：自动设计
构图：自动设计
目标模型：Midjourney
画幅：9:16
数量：5条
大致说明：
负面提示词：不要有水印，不要有logo，不要有变形，不要有空白黑边
地域（可选）：
```

| 面板 | 职责 | 选择与默认 |
|---|---|---|
| 01 题材 | 世界背景与基础气质 | 不自动加入任何特定建筑、生物或人物；用户选择，可自定义 |
| 02 元素 | 可选灵感与明确必须出现的对象 | 点击或添加默认为参考，可采用、转化或舍弃；逐项明确必须出现才锁定。文本可写“参考：…；必须出现：…” |
| 03 视觉偏好 | 时间、配色、照明、氛围 | 四组独立，自动搭配或自定义；颜色名称不授权增加对象 |
| 04 镜头 | 景别、视角、视野 | 各组默认自动；提供大远景＋超广角快捷组合；不将超广角固定为所有题材默认 |
| 05 风格与复杂度 | 表现风格与内容疏密 | 两组独立且默认自动；纪实摄影、卡通、电影CG、油画等属于风格，简约/适中/密集属于复杂度 |
| 06 构图 | 主体位置、视线组织与留白 | 默认自动；布局不等于镜头、画幅或对象大小 |
| 07 目标模型 | 最终图像模型，可含版本或平台 | 新表单显式预选Midjourney；用户清空或未知模型仍按通用分支，不偷偷改回默认 |
| 08 画幅 | 宽高比 | 新表单显式预填9:16；不固定像素尺寸、镜头或人物占比 |
| 09 数量 | 提示词方案数量 | 默认5，支持1—10，1/3/5/7/9快捷；与对象数量无关 |
| 10 大致说明 | 感觉、画面特点、模糊想法与明确限制 | 新建/重置默认为空；可以只写意图，不必写完整故事或补选对象 |

每个方案必须提供中文提示词和英文提示词各一份，完整、独立可复制，表达同一画面。数量N表示N对，不把翻译算作额外方案。

**元素属性独立：** 角色（自动、主体、辅助、背景）；相对尺度（自动、常规、巨大、微型）；画面占比（自动、渺小、适中、突出或明确占比）；对象数量（自动、单个、多个或明确数量）。主体可以在画面中很小，巨大对象也可以位于远景。自然成人比例与在画面中渺小兼容。自定义百分比必须注明宽度、高度或面积；百分比是待出图核验的设计目标。多个主体允许组成共同焦点，不机械拒绝；全部自动时按说明、对象关系与可读性分配主次，不把选中次序当权重。

**参考与必需：** 元素库是可选灵感，不是创作边界；未选择的候选不进入约束。参考可采用、变化或舍弃，只有明确必须出现的对象须逐方案保留。自然语言“画一只白鹿”“主体是白鹿”等确定要求具有同样效力，不强求“必须”字样；“例如”“可以参考”等不升级为必需。模型可设计库外主体、建筑、生物、人物、现象或空间，始终服从本次意图与明确条件，不机械添加题材标志物。

**条件属性与关系：** 出现要求与角色、数量、尺度、动作、服饰等属性独立。参考对象的指定属性在采用时生效，不隐式锁定其出现；必需对象在每个方案落实明确属性。参考被转化成另一对象时，不得冒称满足原对象的必需条件。参考对象的明确关系及目标需共同成立，也可整组不采用；必需对象的明确关系目标同为必需。工作台必须要求用户显式确认关联目标后原子保存，前后端拒绝不完整依赖，循环按集合校验。未指定关系目标时可自由设计相容对象，不能违反排除项。

配饰和局部结构不因常见宿主关系而必然增加穿戴者或完整生物；独立静物意图优先，其他对象依实际创作意图设计。人物不再需要先从库中启用，也不默认每图加入。明确“无人”“只画静物”“只包含这些对象”等要求须遵守；不能为凑尺度参照而违反它们。

**自动与随机：** 两者均可按意图构思主体与关系、选择库外内容，随机仅影响未锁定项。多方案可在主体、核心概念、结构、关系、轮廓或构图上形成实质差异，不能只换色；已构思的第一个主体不成为其余方案的额外硬约束。必须对象不等于必须充当主体，除非明确role或文字指定。concept说明核心构思与实际采用的灵感，design只总结最终采用的画面。

**跨面板协调：** 镜头、媒介、画幅、数量、地域、光色及明确文字要求继续有效；仅元素选择默认为参考。参考与硬限制冲突时可舍弃参考，不阻断生成；必需与禁止或其他硬条件无法兼容才澄清。普通缺省直接设计，不依面板顺序覆盖；简约与精细写实可并存，密集不覆盖排除要求。

**当前工作台契约：** V15配套完整V11；schemaVersion=4、scene-forge-backup-v4、scene-forge-workspace-v15。每个元素有唯一对应的elementSettings，presence取reference或required；designOptions只保留exploration，取消旧全部包含/选配与allowExtra开关。人物属性与原十维数据保留；说明默认为空，负面默认与明确清空不变。草稿、预设、历史、备份、下载都保存出现要求和原意图。只读取新格式，不导入或迁移旧v3；旧数据通过保留的V14查看，独立接口配置与密钥沿用。无效结果不补造design，损坏存储不自动覆写。

**历史实现范围：** 下述schemaVersion=2与旧格式复用是V8配套工作台V11的历史记录，不适用于当前V15。工作台V12—V14使用schema3，V14接入规范V10；这些已交付目录与数据保留原样，不执行下述历史迁移。

**旧输入兼容（仅适用于支持旧格式的历史工作台）：** 历史中原九项保持原文，不追补新模型、画幅、数量、属性或负面默认。复用到新表单时，旧必须包含映射到元素，旧想画什么作为场景候选、旧视觉偏好和创作自由度保存在可见兼容区。旧场景多选仍是候选，不变成每条必须全部出现；旧必须项仍逐方案保留。清空新负面或目标模型保持清空。自然语言或旧接口未指定目标模型仍用通用描述；Midjourney只是新表单可见预选值。

上述历史工作台内部记录schemaVersion=2、十维字符串及负面字段、elementSettings与designOptions，迁移时另存legacy兼容输入。属性只绑定当前存在的元素，删除元素同时清理其属性。清空视觉偏好面板同步解除旧视觉偏好；清空大致说明面板移除说明及旧兼容要求、恢复默认设计自由度。历史、预设、备份和下载保留这些信息；密钥不属于创作输入。具体题材库和候选名称仅在工作台维护，不随本规范复制。

### 4.0.1 负面提示词的默认值与使用规则

默认值必须直接填写在输入模板与页面输入框中，作为可编辑的实际内容，不仅作为占位提示：

```text
负面提示词：不要有水印，不要有logo，不要有变形，不要有空白黑边
```

- 本字段是跨题材的初始偏好，可以修改、增删或清空，不是不可覆盖的全局禁令。
- 新建或重置输入时预填默认值；未提供该字段的旧格式需求、旧草稿和旧预设，作为新任务使用时补入默认值，并在本次输入摘要中显示。
- 用户明确填空、清空或写“无”时，表示不添加本字段的负面要求，不自动恢复默认，也不解释为“由模型自由补充负面要求”。用户自定义内容替换默认值，不偷偷合并旧默认。其他字段明确要求的约束仍然有效。
- 默认的“变形”指不需要的形体或结构异常，不否定用户有意设计的幻想造型；“空白黑边”指画面外围多余空白边缘或黑色条带，不排除构图留白、深色物体或正常阴影。
- 将实际填写内容解析为“约束 → 排除内容”，保留原文用于追溯；与必须包含内容发生实质冲突时，先澄清取舍，不静默删除任何一方。
- 每个方案的中文与英文提示词均落实相同排除意图。根据目标平台与版本采用已核实的排除方式或合适的正向替代表述，不把所有模型都当作支持同一负向参数。
- 保存草稿、预设、备份和新生成记录时保留本次实际值，包括空值；旧历史只显示当时已记录的输入，不追补默认值或改写原提示词。将旧历史恢复为新的创作输入时，缺失的新字段使用当前默认值，生成前可以编辑。
- 这些是生成约束与检查项，不能保证出图绝无水印、logo、变形或黑边；结果需按第 12 节检查。

目标模型填写的是最终出图平台或模型，可加具体版本与运行界面；未填写时按通用自然语言处理，不默认 Midjourney。具体分流与官方来源见第 11.3—11.4 节。

### 4.0.2 地域选项与作用范围

“地域”描述画面的地理或文化语境，也可指定地域美术参考；不指用户所在地、账号地区或网络位置。它是可选创作条件，适用于不同题材与模型，不只用于Midjourney。

- **填写方式：** 可写真实国家、地区、城市、文化区域，也可写虚构地域或明确的地域融合。可追加时代、作用对象、影响范围与必须/偏好等级，但这些不是新的必填项。具体地域候选库属于工作台，本规范不维护地区清单。
- **默认与清空：** 默认未指定；未填写、空值、“无”“不限”均不增加本字段的地域限制，也不固定回退到某个国家或城市。题材和说明中已有明确地域仍须识别；清空本字段不删除其他字段的要求，明确取消全部地域限制时按本次修订处理。
- **自动设计：** 用户明确填写“自动设计”或“由你设计”时，可按题材与已选对象选择相容地域方向，并在设计摘要标为助手选择；不把未填写等同于授权随机选择真实地区。随机探索仅在地域未锁定且用户允许地域变化时启用。
- **含义分开：** 场景发生地、对象的文化来源与美术参考不是同一字段含义。只写地名时，优先作为场景或对象的地域语境；抽象图案、独立产品等不存在场景地点的任务，可作为对象设计参考并注明。不自动把它扩展成整图媒介、统一色调或人物身份；关键歧义影响必须项时再澄清。
- **影响范围：** 可作用于已有环境的地形、气候与空间组织，已有建筑的结构与材质，已选服饰或道具的形制工艺，或明确指定的美术语言。地域作用于本次实际设计的内容，不强制增加地标、宫殿、宗教符号或人物；对象是否出现由意图、参考与必需规则决定，独立服饰不因地域必然增加穿戴者，地域不推定人物族裔、国籍或性别。
- **优先级与冲突：** 用户指定地域属于明确条件；标为偏好时允许有限调整。根据地域推导的设计不能覆盖已锁定的时代、对象、媒介、配色、光线、镜头或数量；不能因地名自动补雨夜、霓虹或某种服装。明确地域与其他必须项无法兼容时请求取舍，不静默替换任何一方。
- **多地域：** 区分一个画面的融合、不同对象分别采用、多个方案之间分配，以及候选池待选。用户未说明且解释会改变必须内容时先澄清。融合要说明各地域影响哪个对象或层面，不能只堆地名；已锁定地域不得为制造差异而替换。
- **双语与记录：** 每对提示词保持地域语义、时代、作用对象、具体特征及融合关系一致。保留原输入与本次解释，不把旧历史缺失的地域补造为已使用；规范设计记录与工作台schema分别维护。当前V15使用schemaVersion=4保存可选地域，不补造旧历史；旧版数据保持原样。

### 4.1 需求提取

以下是提示词助手需要识别或按授权补齐的内部信息，不是另一份用户必填表。用户默认使用第 4.0 节的简洁格式，也可以用自然语言提出需求：

| 输入项 | 要识别的内容 |
|---|---|
| 用途 | 图片用于什么场景 |
| 画面类型 | 角色、道具、环境、叙事、海报等 |
| 题材 | 已指定题材、混合题材或待探索方向 |
| 地域（可选） | 地理/文化/虚构语境、时代与作用范围；未指定不强加，明确融合需分工 |
| 创作意图与参考 | 感觉、特点或模糊念头；参考对象及采用时属性，与必须内容分开 |
| 必须内容 | 明确要求的主体、数量、特征、动作、关系、文字等 |
| 美术偏好 | 媒介、色彩、材料、情绪、参考 |
| 生成模式 | 探索、系列或定稿 |
| 输出要求 | 模型、数量、提示词语言、画幅与尺寸 |
| 差异要求 | 哪些应保持一致，哪些应主动变化 |

### 4.2 缺失信息处理

1. 用户明确指定的内容优先，不用默认值覆盖。
2. 缺失信息会改变任务性质或造成无法兼容的设计时，集中询问关键问题。
3. 普通设计选择可以采用暂定值继续工作，并简短标注。
4. 不把缺失信息统一补成雨夜、紫蓝霓虹、低机位或其他固定套路。
5. 不适用的字段可省略；重要但未知的字段记录为未知，不能虚构。
6. 模型版本或能力未知时，不编造版本号、参数值或支持能力。

### 4.3 按画面类型启用模块

| 类型 | 优先设计 | 可按需省略 |
|---|---|---|
| 角色 | 面部识别、轮廓、姿态、服饰、身份 | 复杂城市背景 |
| 载具、道具 | 功能、结构、材料、尺度、展示角度 | 人物故事 |
| 环境、建筑 | 空间、体量、基础设施、生活系统 | 远处人物的微小细节 |
| 叙事插画 | 瞬间、行为、关系、情绪证据 | 完整世界历史 |
| 海报、封面 | 焦点、信息层级、文字区域、裁切 | 无关背景细节 |
| 产品展示 | 形态、材质、完整性、背景 | 与用途无关的叙事 |
| 图案、抽象图像 | 节奏、形状、重复、颜色、表面 | 人物、镜头和故事 |

### 4.4 生成模式

- 探索：扩大概念、轮廓、空间与美术方案的差异。
- 系列：锁定指定的世界、美术或身份特征，变化单图内容。
- 定稿：保留已认可设计，只修改目标问题。

## 5. 设计流程与顺序

### 5.1 默认设计顺序

```text
创作意图、必须与排除要求（区分可选参考）
→ 用途、画面类型与交付要求
→ 画幅
→ 题材边界、地域条件（如有）与美术方向
→ 一句话核心概念
→ 主体、行为和关系（允许库外创作，有选择地吸收灵感）
→ 景别、观察位置、空间与构图
→ 主体轮廓、结构与尺度
→ 光线、色彩、材料
→ 必要细节与使用痕迹
→ 冲突及差异检查
→ 模型适配与最终提示词
→ 出图核对与修订记录
```

这是默认决策流程，允许回退与迭代。特定光线或材质可以成为创意起点，但必须进一步落实空间与主体关系。

### 5.2 各步骤产物

| 步骤 | 工作 | 产物 |
|---|---|---|
| 需求理解 | 区分必须、偏好、自由项与未知项 | 任务说明 |
| 方向确定 | 选择题材规则、解释地域作用范围及美术约定 | 本次设计边界 |
| 概念设计 | 确定主要表达与创新 | 一句话概念 |
| 元素组织 | 确定角色、用途、位置与交互 | 元素关系表 |
| 画面设计 | 确定画幅、镜头、尺度与裁切 | 单图规格 |
| 外观完善 | 推导形态、材料、光色与细节 | 完整设计稿 |
| 检查修订 | 排除冲突、重复和不可见细节 | 修订方案 |
| 模型适配 | 压缩、转写、配置 | 最终提示词与参数 |

### 5.3 最终提示词排列

可采用以下默认顺序，再按模型和任务调整：

> 主要画面与主体 → 关键行为和关系 → 空间构图 → 主要造型 → 光色、材料与媒介 → 必要限制。

地域描述随其作用对象放置：场景地域可随环境叙述，服饰地域随服饰叙述，仅作美术参考时随风格叙述。用少量可见特征补足地域名称，不将地名一律放在开头或假定固定权重。

环境图可以先描述场景整体；角色图可以先描述角色；材质研究可以先强调表面与媒介。该顺序是写作规则，不是跨模型通用的注意力权重公式。

**按画面类型组织首句：** 首句优先概括本次最重要的可见画面，随后展开支撑它的关系和细节。叙事场景可交代核心主体、所处环境与一个可见瞬间或状态；环境与建筑图可先交代整体空间及主要体量关系；角色和产品图可先交代对象身份、关键轮廓或展示状态；图案与抽象图像可先交代形状组织、节奏或颜色结构。仅纳入本次重要信息，不要求每个首句填满这些项目，不为非叙事画面强加事件、人物或故事。

**从字段转成画面：** 十维输入与内部设计表用于组织条件，最终正文按画面逻辑连接实际采用的对象、动作、位置、尺度与光色，不机械逐项复述字段名。先建立核心画面，再展开影响理解的关键关系；修饰语靠近其作用对象，避免把颜色、材质或动作错误分配给其他对象。根据目标模型与任务选择连贯句、短句或简洁词组，不固定句数、字数或一律使用长段落。

**展开与取舍：** 在保留必须项的前提下，先保证主体和关系可读，再补必要外观与环境细节。同一对象可以同时承担尺度参照、光源、空间组织或情绪线索等作用，但不强求每个对象多用途，不为凑齐作用而增加对象。可选变化属于方案建议；未被选用时不进入本方案的确定描述。

## 6. 题材包与美术设定

### 6.1 题材包标准结构

每个题材包包含：

1. 题材定义与适用范围。
2. 时代、地域与文化背景。
3. 世界运行、技术或超自然规则。
4. 现实程度：真实工程、可信虚构、超现实或象征性表达。
5. 核心识别线索与可选美术方向。
6. 通用分类下的候选元素。
7. 元素组合逻辑与依赖关系。
8. 常见刻板表达及可拓展方向。
9. 允许的跨题材融合与需要避免的冲突。
10. 参考资料、来源及适用范围。

研究得到的事实、特定作品设定、设计推断和原创设定应区分记录。单个作品的设定不能自动上升为整个题材的通用规则。

### 6.2 美术设定标准结构

| 项目 | 要明确的内容 |
|---|---|
| 媒介 | 摄影、绘画、插画、三维或其他形式 |
| 形状语言 | 曲直、厚薄、尖圆、对称、重复与轮廓特征 |
| 色彩 | 主色、辅助色、强调色以及各自分布 |
| 明暗 | 主要亮区、对比关系、主体与背景分离方式 |
| 照明 | 光源、方向、范围、软硬与环境反射 |
| 材料 | 表面、工艺、使用状态和组合规则 |
| 密度 | 主体细节、辅助细节、背景信息与留白 |
| 情绪 | 希望表达的感受及其可见依据 |

“高级”“震撼”“电影感”等词可作为方向，但应进一步转译为可检查的视觉关系。不得要求所有区域同样明亮、锐利或复杂，除非任务确实需要这种表达。

将美术方向落实到正文时，按任务需要检查以下归属：

| 项目 | 表达要求与边界 |
|---|---|
| 色彩归属 | 将主色、辅助色或强调色关联到明确对象、区域或光线；整体调色要求可作用于全图，不必逐物着色。避免只列颜色却无法判断各自分布 |
| 照明关系 | 对影响焦点或空间阅读的光线，说明光源、受光对象或区域及关键可见效果；方向、范围、软硬、反射或透射按需补充，不为每盏灯机械补齐全套参数 |
| 主媒介与辅助风格 | 多种表现方式并用时明确主要媒介及辅助参考承担的特征；允许融合，避免把未选定的媒介候选全部并列为确定要求。用户明确锁定的风格优先 |
| 细节作用与分布 | 细节宜帮助识别对象、体现结构材质、建立关系尺度、组织空间光色或表达情绪；装饰和重复也可服务节奏。依据焦点、景别与复杂度分配细节，按需保留低信息区域，不将“细节丰富”解释为全图同等密集 |
| 情绪的可见依据 | 按当前尺度选择姿态、朝向、对象间距、明暗或环境状态等证据。微小人物可通过身体朝向与群体行为表达情绪，不依赖远景中不可辨的面部微表情；无人物画面用已有对象和空间表达 |

这些关系应服从本次明确条件；未指定部分才由助手补齐。简约不等于低材质质量，密集也不等于允许增加明确排除的对象。通用质量词可以保留为偏好，但不能代替具体视觉要求；“8K”等尺寸用语继续按8.1区分实际交付规格。

### 6.3 地域如何转译为视觉设计

地域与题材可以组合，同一题材允许不同地域；同一地域也可采用不同媒介、复杂度和时代。设计时依次明确“地域语义 → 作用对象 → 可见特征 → 与锁定条件的协调”，按画面类型选用，不要求补全世界系统。

| 作用层面 | 可转译的信息 | 设计边界 |
|---|---|---|
| 环境与空间 | 已有地形、植被、气候线索、街巷或聚落组织 | 不因地域覆盖明确天气或强制加入标志物 |
| 建筑与设施 | 已选建筑的体量、屋顶、开口、结构与材料工艺 | 不自动添加地标；真实历史形制需核实，幻想改造标为原创 |
| 服饰与道具 | 已选对象的剪裁、构造、材料、纹样与使用方式 | 不推定人物身份，不补穿戴者，不把整片地区当作单一服装 |
| 美术语言 | 明确要求的装饰、形状、笔触或色彩组织参考 | 与摄影、CG等表现媒介分别记录，不覆盖已锁定风格 |

选择与当前构图和尺度相符的少量特征，避免只写笼统地域标签或堆砌符号。真实地区具有内部差异；需要准确性时细化地点与时代并核实来源；创作性的混合或推导标为设计建议，不冒充地域事实。产品、图案或抽象任务可只启用工艺/美术层，或将地域标为不适用。

地域差异应落实空间组织、轮廓、结构、材料或对象关系，而非仅换色。未指定的时代不能由地域自动推定为古代或未来；无法确认的历史细节保留待核实状态。

## 7. 元素库与关系规范

### 7.1 通用元素分类

下表的赛博朋克内容是候选示例，不要求每张图全部出现。

| 通用类别 | 赛博朋克候选示例 |
|---|---|
| 人物与群体 | 居民、信使、维修师、企业职员、街头艺人 |
| 生物与人工生命 | 服务机器人、仿生宠物、改造生物 |
| 建筑与空间 | 住宅、诊所、地下市场、企业大厅、屋顶花园 |
| 交通网络 | 高架轨道、磁悬浮线路、空中航道、立体匝道 |
| 交通节点 | 车站、换乘厅、货运港、维修坞、起降平台 |
| 载具 | 赛车、摩托、通勤舱、货运无人机、维修车 |
| 能源与工业 | 配电柜、储能站、冷却塔、热交换器、生产线 |
| 通信与计算 | 天线、光纤管道、数据中心、街头终端 |
| 信息与投影 | 全息导览、广告投影、透明屏、腕部界面 |
| 管理与边界 | 门禁、检查站、摄像头、警戒线、区域标识 |
| 商业与生活 | 售货机、餐摊、洗衣房、充电柜、回收站 |
| 服饰与随身物 | 工作服、防护装备、身份牌、工具、通信装置 |
| 自然与生态 | 河道、温室、人工绿地、野生植被、动物 |
| 时间与使用痕迹 | 磨损、翻修层、补丁、旧标识、遗留设施 |
| 气候与光学现象 | 雨、雾、蒸汽、粉尘、反射、局部光束 |
| 文化与象征 | 涂鸦、地方纹样、仪式空间、音乐设备、纪念物 |

更换题材时保留分类，替换具体设定。例如，交通网络可以对应云桥或水道，信息系统可以对应旗语、告示或符文。自然、抽象或图案类任务无需启用完整社会系统。

### 7.2 元素属性

关键元素按需记录：

- 编号与类别。
- 名称、身份或功能。
- 视觉角色：主体、辅助、背景或氛围。
- 数量、轮廓、结构、材料与颜色。
- 动作、状态、使用痕迹。
- 位置、相对尺度及必须保留的特征。
- 可变化维度、关联元素与使用条件。

关联元素是选材提示，不代表必须全部加入画面。

### 7.3 元素关系

| 关系类型 | 示例 |
|---|---|
| 空间 | 上方、穿过、围绕、连接、遮挡 |
| 行为 | 操作、维修、等待、搬运、观察 |
| 功能 | 供能、承载、导航、保护、检查 |
| 光影 | 照亮、投影、反射、透射 |

主要对象不能只以关键词并列，应说明关键关系。优先使用明确对象名称，避免含混的“它”“旁边那个”等指代。

**关键关系必须落到正文：** 对决定本次画面理解的关系，明确关系两端的对象，以及连接它们的动作、空间、功能或光影状态；不能仅在内部关系表或设计摘要中记录。无需把所有对象两两连接，背景和装饰允许按区域或群组概括。能够唯一指向对象的代词可以使用，存在多个可能指代时改用明确名称。

**尺度与可见范围：** 需要强调大小时，可用已启用对象之间的相对体量、邻接、遮挡和可见范围支撑“巨大”“微小”等方向，同时区分世界相对尺度与画面占比。尺度参照可在开放设计中按意图选取，但不得违反无人、静物或对象范围等明确限制；也可通过空间、透视与裁切表达，不强求参照物。对象露出哪个部位、哪些部分出画或被遮挡，应与动作和镜头一致；不把局部可见误写成完整展示。

**情绪与状态：** 关系描述应使用当前画面能呈现的姿态、朝向、距离或交互证据。自动设计仅补充未锁定的信息，将情绪转成可见设计时尊重原意，不机械套用攻击、逃跑等固定故事；硬性条件冲突时按2.2与4.2处理。

## 8. 三个画面控制模块

### 8.1 画幅与交付规格

负责画布形状和最终文件要求。

| 字段 | 内容 |
|---|---|
| 使用用途 | 壁纸、封面、海报、概念图等 |
| 画幅方向与宽高比 | 横向、竖向、方形及具体比例 |
| 目标像素尺寸 | 最终宽度与高度 |
| 生成尺寸 | 目标模型实际支持并选用的尺寸 |
| 输出格式 | 按透明、压缩、编辑需求选择 |
| 背景要求 | 完整场景、纯色或透明 |
| 多尺寸适配 | 是否需要同一设计的其他比例 |
| 印刷规格 | 实际尺寸、出血、分辨率及色彩要求，按需启用 |

画幅比例应在构图前确定或采用明确的暂定值。交付像素尺寸应在最终图像交付前明确；只生成提示词且未指定交付尺寸时，可保持未指定。

画幅比例、像素尺寸、主体占比和世界中的相对尺度是四个不同概念。“4K”“8K”等文字不构成实际输出尺寸的保证。

### 8.2 镜头与空间表达

负责观看方式及空间呈现。以下列出可选择的字段与取值，不规定固定镜头。

用户明确指定镜头时遵循其要求；未指定时，由助手根据主体、表达重点、空间关系和画幅选择。广角、中远景、平视或浅景深都不是本规范的全局默认设置。若要求相互冲突，先调整未锁定的设计，无法兼容时再向用户确认。

| 字段 | 内容 |
|---|---|
| 景别 | 大远景、远景、全景、中景、近景、特写 |
| 观察方位 | 正面、侧面、背面、三分之四视角 |
| 观察高度 | 地面附近、视线高度、高处、空中 |
| 俯仰角度 | 平视、俯视、仰视、垂直顶视 |
| 画面倾斜 | 水平稳定或有意倾斜 |
| 观察距离与视角 | 近距离广角感、自然视角、远距离长焦感 |
| 投影方式 | 透视、正交、等距或平面化表达 |
| 空间层次 | 前景、中景、背景与纵深 |
| 对焦与清晰范围 | 焦点、浅景深、深景深或全图清晰 |
| 运动表现 | 静止、动作凝固、运动模糊、追随效果 |

具象画面通常优先确定景别、观察方位、观察高度或角度及主要清晰对象。平面图案等任务可以不使用镜头模块。

相机型号、焦距、光圈不是必填项。先描述希望获得的视觉效果；需要时再补充摄影术语。透视与观察位置有关，不能全部归因于焦距。生成描述中的相机参数不保证真实光学模拟。

静态图中的运动应写成可见结果，例如背景拖影、飞溅水滴。推进、环绕等连续运镜应拆成静态视点，或另行使用视频规范。

### 8.3 主体尺度与裁切

负责对象在画面中的位置、大小、完整性与后续适配。

| 字段 | 内容 |
|---|---|
| 主体位置 | 居中、偏置、上下左右区域 |
| 主体占比 | 明确占画面宽度、高度或面积 |
| 对象相对尺度 | 人与建筑、车辆与轨道之间的大小关系 |
| 可见范围 | 全身、半身、完整物体、局部结构 |
| 裁切规则 | 可出画与不可裁切的部位 |
| 遮挡规则 | 可以被遮挡与必须可辨的特征 |
| 留白区域 | 标题、排版与视觉呼吸空间 |
| 安全边距 | 关键内容与边缘的距离 |
| 多画幅保护区 | 更换比例时必须保留的共同内容 |

百分比是设计目标，应在出图后检查。若多画幅无法通过裁切保留关键内容，应分别构图，而非强行裁切。

### 8.4 联合检查

- 远景中的微小面部细节是否实际可见？
- 特写、完整物体和大量留白是否兼容？
- 浅景深是否遮蔽必须辨认的背景关系？
- 仰视或遮挡是否隐藏关键结构？
- 主体数量、画幅与占比是否留有足够空间？
- 标题区、主体位置和后续裁切是否冲突？

必要时调整镜头、占比或细节要求，也可以另做细节图。

## 9. 创意、差异与连续性

### 9.1 单图创意方法

以固定项、变化项和关联规则共同设计：

> 身份与用途 → 环境条件 → 功能需求 → 轮廓结构 → 材料与细节。

创新可来自功能转换、身份转换、时间叠加、材料、尺度、对象关系或观察视点。主要创新应影响概念、轮廓、用途、关系或观看方式。

默认先确立一个主要创意，再选择支持它的线索。复杂群像、全景或装饰图案可以有多个焦点，但应明确组织方式。

人物差异不应只依赖发色与灯光；载具差异不应只依赖涂装与发光条。应比较面部结构、轮廓、比例、功能、服装剪裁和主要结构。

### 9.2 批量差异

先制作方案差异表，再写最终提示词。比较维度包括：

- 核心概念与使用场景。
- 主体类别、身份与轮廓。
- 主要功能、结构和材料。
- 关键元素关系。
- 视点、景别与构图。
- 光色与时间天气。

可暂以“至少改变两个重要维度”作为探索模式起始规则；这属于待验证的工作约定，不是质量保证。用户要求同一对象多视角时，身份和结构应保持一致，不执行无关去重。

### 9.3 连续性记录

记录系列固定项、本次变化项、已使用组合和修改原因。跨批次去重依赖可访问的历史记录；没有历史时，不宣称已实现长期去重。

## 11. 模型适配与交付格式

### 11.1 适配步骤

1. 筛选可见且重要的信息，删除无助于画面的内部说明。
2. 明确对象、动作、位置、颜色归属和关系。
3. 将抽象意图转换为姿态、物件、空间、光色等可见依据；有地域要求时按4.0.2与6.3明确作用对象和可见特征，不擅自扩展人物或背景内容。
4. 根据模型选择描述长度和组织方式，不统一要求长提示词或短提示词。
5. 从本次负面提示词提取排除项，按第 4.0.1 节判断默认、用户修改和明确清空。根据平台与版本转换排除项，不默认所有模型均有负向提示词字段；不把未经核实的参数直接拼入提示词。
6. 区分内容、风格和身份或形态参考，注明各自目的。
7. 核实参数支持与版本，不在基础规范中固化未经验证的通用参数组合。
8. 每个方案分别生成中文与英文提示词；两份都完整可用，不把中文写成英文的简短摘要。保持主体及数量、行为、关系、地域及其作用范围、镜头构图、光色材料、必须项、排除项和设计意图一致，不擅自增加或遗漏内容。允许自然语言习惯不同，不要求逐词直译。
9. 模型参数名称、数值、比例、参考标识及必要专有名词在两份中保持一致。参数名称不翻译；参数中的自然语言排除对象允许等义翻译，不改变排除范围。配置可以共享列出，若嵌入提示词则两份都应一致。修改任一语言的设计内容时同步更新另一份，并检查语义一致性；不要声称双语输入必然生成完全相同的图像。

交付前进行一次正文精简与语义检查：

- 合并重复表达同一属性或氛围的词句，优先保留具体、可见且有明确归属的要求；用户明确要求的强调或有意重复应保留。
- 清理影响理解的含混指代、漂移的修饰对象和相互竞争的未决描述；同名近义词若实际指向不同对象类型，应明确类别，不能简单视为冗余删除。
- 对表示尚未选择的“甲/乙”“或”等候选，普通自由项在授权范围内选定，影响必须项的歧义按4.2处理；若用户明确要求融合或允许多种结果，应准确保留其关系，不机械删除所有斜杠或“或”字。
- 删除无助于本次画面的内部说明和自由补充的无作用细节；当前景别下不可见的明确要求不能静默删掉，应检查是否能调整未锁定镜头或设计，必要时澄清。
- 精简后逐项核对主体、数量、对象关系、光色、可见部位、必须项、排除项与已核实参数，防止缩短文字时改变设计；不设跨模型统一字数上限。
- 中文与英文依据同一份已确定画面转写；修改任何一份的内容时同步检查另一份。逐项等义不等于逐词直译，也不保证两种语言生成相同图像。

图像尺寸应落实到工具设置与后续处理。风格参考、对象参考、随机种子等功能不能互相替代；具体适用范围按目标平台核实。

### 11.2 默认交付格式

每组方案交付：

1. **方案名称**。
2. **核心设计**：一句话概念及主要创新。
3. **关键画面规格**：画幅、镜头、主体安排与美术方向。
4. **中文提示词**：完整画面描述，独立代码块，可单独复制。
5. **English Prompt**：同一画面的完整英文描述，独立代码块，可单独复制。
6. **模型配置**：两种语言共享的已核实参数、参考使用方式或尚未确定项。
7. **差异与验证项**：与其他方案的区别及需要出图检查的内容。

两份可复制提示词必须各自包含本次实际负面要求或等价正向表述，不能只在设计摘要或模型配置中提到。如果平台需要独立负向输入栏，在各语言交付块内标注正向与负向文本，并在模型配置中说明分别放入哪个输入栏；不得声称一个混合文本可直接用于所有平台。明确清空时不额外附加默认负面段落。

可在每种语言的完整提示词块内，按需分段呈现“主要画面”和“光影与风格”，也可合成连贯正文。分段只为阅读，不要求固定标题或分栏；复制该语言的提示词时应能取得全部画面、风格及本次实际约束。需要独立负向输入栏时仍按上段标明分栏用途，不能因展示合并而混淆提交方式。模型配置继续单列；可选调整建议放在提示词块之外，并明确尚未应用，不能把“可以增加”等候选混入当前确定方案。

完整设计卡作为检查依据，默认不必全部展示。用户要求“只输出提示词”时，省略设计说明，仍提供中文和英文两段；按方案配对排列，不把 N 份中文与 N 份英文拆成难以对应的两组。语言不额外增加为用户必填输入；十个主面板之外保留独立负面提示词及可选地域补充项。

### 11.3 目标模型规则与官方来源

“目标模型”是最终出图的模型；工作台配置中的 OpenAI / DeepSeek 是编写提示词的文本服务，二者独立。例如用 DeepSeek 编写 FLUX 提示词，仍必须选用 FLUX 规则。用户可直接在原有目标字段补版本和运行平台，无需增加必填项。

先识别目标家族，再确定版本与运行入口。家族匹配仅启用相应的保守写法，不等于具体版本和第三方界面已验证；未经核实不强行选最新版本。空项或未知模型使用通用自然语言并标记待适配；同时填写多个模型时先澄清，不悄悄选其中一个。保留用户的原始目标名称。

#### 11.3.1 Midjourney的地域表达与证据边界

**官方依据（查阅于2026-10-22）：** [Prompt Basics](https://docs.midjourney.com/hc/en-us/articles/32023408776205-Prompt-Basics)建议用明确措辞描述环境、媒介等重要画面信息；[Parameter List](https://docs.midjourney.com/hc/en-us/articles/32859204029709-Parameter-List)区分正文与尾部参数，所查列表未列出独立地域参数。这些是家族级表达依据，不代表某个版本对特定地域的还原能力已验证。

**项目设计推断：** 地域词及其具体视觉特征可能引导Midjourney对环境、造型或整体观感的解释；影响程度、方向和稳定性待实际出图验证。不能据此声称某个地区必然对应某种风格、存在固定地域权重，或地域优先于其他明确条件。

**执行规则：** 将地域和适用对象写入自然语言正文，补充必要可见特征；地点描述与地域美术参考分开表达。仅要求某对象带地域特征时，不把地域标签扩散到全图。不得生成虚构的地域专用参数，不自动切换版本或添加风格强度、种子、参考图等设置。其他模型使用其自身分支表达同一设计意图。

**验证方式：** 若后续要求测试，分别比较无地域、仅地域名称、地域名称加具体视觉特征三组；保持题材、对象、媒介、镜头、画幅、模型版本、其他设置及参考条件一致，观察多个样本，记录地域识别线索、风格漂移和锁定条件遵守情况。本轮未执行此测试，不预先宣称收益。

## 12. 验收与迭代

### 12.1 提示词交付前

- 核对可选地域：原值、空值、作用对象与融合分工是否保留？是否把地域推断误当事实、偷偷加入人物或地标、覆盖锁定风格？是否虚构地域参数或效果保证？
- 核对十维输入、元素属性和说明：角色、世界相对尺度、画面占比、对象数量不混淆；出现要求与条件属性分开，允许按意图设计人物，但明确无人及其他禁止要求仍生效。
- 核对随机只影响未锁定项、参考可舍弃而必须项逐方案保留、必需关系目标闭包完整；风格与复杂度独立，空负面不恢复默认。


- 意图是否在核心概念、主体和关系中落实？多方案是否具有实质差异？参考是否被误当成必需？
- 实际design是否只列采用对象，与双语正文一致？必需对象及条件属性是否落实？
- 明确需求是否全部覆盖，假设是否标注？
- 负面提示词是否使用本次实际值？默认是否可追溯，明确清空是否被尊重，是否与必须项冲突？
- 题材、美术、媒介和内容是否分清？
- 核心概念是否明确？
- 主要元素是否有功能、位置、尺度与关系？
- 重要细节在当前镜头和占比下是否可见？
- 画幅、镜头、空间、裁切、留白是否兼容？
- 必须项是否冲突？是否存在含混指代或属性归属？
- 创意是否超出换色和装饰？系列固定项是否保持？
- 模型配置是否核实？最终提示词是否存在模板残留？
- 是否根据目标图像模型而非文本服务选择规则？来源范围、查阅日期和实际版本是否区分？非 Midjourney 是否混入其专用参数？负向输入能力是否按版本核实？
- 每个方案是否都有完整中文和英文？数量 N 是否恰好对应 N 对？
- 中英文的主体数量、动作、空间关系、地域及作用范围、镜头、光色、必须项与排除项是否一致？参数是否相同？
- 两种语言是否都可独立复制使用，且没有把一份缩减为摘要？

对本轮表达细则再检查：

| 检查项 | 通过条件 |
|---|---|
| 首句与画面类型 | 能概括本次核心画面；不强制非叙事任务具备故事或人物，不因固定顺序损失重要信息 |
| 关系与尺度 | 关键关系实际进入每份正文，关系对象明确；世界相对尺度、画面占比、局部可见与完整展示不混淆，没有为参照而增加明确排除的对象 |
| 光色与媒介 | 重要颜色、材质、光源及受光效果归属可辨；多种媒介有明确分工或融合意图，未覆盖锁定条件 |
| 细节与情绪 | 细节分布服务本次焦点、节奏和复杂度；情绪依据在当前景别可见，不强求微小人物面部细节或全图同样锐利 |
| 精简与完整 | 重复及无作用的自由补充已处理，必须项和明确排除项未被删改；没有未解释的占位符或未决候选，没有将可选建议当成既定设计 |
| 双语逐项对照 | 对象类别与数量、动作状态、方位与前后层次、关系两端、可见部位及遮挡裁切、相对尺度与画面占比、颜色材料和光源归属、媒介、地域、约束及参数逐项等义；不把单侧新增内容当成翻译润色 |
| 完整复制 | 每种语言的完整交付块包含该方案全部必要内容；分段不造成风格或约束遗漏，独立负向栏和共享模型配置的使用方式清楚 |

以上为文档与提示词检查；实际画面中的关系遵守度、尺度、光影和双语效果仍需按12.2出图验证。

### 12.2 出图后

- 必须项是否兑现？
- 有地域要求时，其指定范围内的视觉线索是否可读？是否误改其他对象、媒介或光色，产生无依据的地域符号？未指定或不适用时不强制地域验收。
- 本次负面要求是否兑现，例如水印、logo、异常变形和多余空白黑边是否出现？已清空或不适用的项不按默认强制验收。
- 题材身份、视觉焦点和信息是否可读？
- 结构、尺度、交互、光影和材料是否协调？
- 创新点是否实际可见？
- 系列一致性和方案差异是否成立？
- 文字、裁切、尺寸和交付要求是否符合？

分别记录“通过、部分符合、不符合、不适用”及可见证据。必须项不符合时，不能用整体审美评分抵消。

### 12.3 修改原则

优先判断问题来源：设计矛盾、表达含混、参数配置或模型执行。每轮围绕明确问题修改；比较版本时尽量保持无关设置一致，并观察多个样本。

记录提示词、模型版本、设置、参考、结果与修订原因。不以一张偶然成功的图片证明规则有效。未实际出图时只能报告设计与提示词检查，不能报告图像验收通过。

## 13. 应用示例：赛博朋克车站设计（本章设置仅用于本例）

本章是一份填写后的示例设计卡，不是全局配置。下面的 16:9、广角中远景、斜向观察、场景为主体等设置仅为这个车站画面所选，不能自动套用到其他题材或其他画面。通用字段见第 8 节，适用范围规则见第 2.3 节。本例未经过出图验证。

### 13.1 本例的任务与概念

- 任务：设计包含轨道与全息投影的赛博朋克环境概念图。
- 暂定画幅：16:9 横向；交付像素尺寸尚未指定。
- 核心概念：暂停运营的高架车站，被居民改造成维修市场。
- 主要创新：公共交通空间被重新使用，旧设施与新生活叠加。
- 本例负面提示词：不要有水印，不要有logo，不要有变形，不要有空白黑边。此处采用初始默认，其他任务仍可修改或清空。

### 13.2 本例的元素与关系

| 元素 | 角色 | 设计与关系 |
|---|---|---|
| 改造站台 | 主体空间 | 立柱、轨道与摊位组织纵深 |
| 中央维修台 | 主要焦点 | 居民围绕它修理家用机器人 |
| 轨道 | 空间骨架 | 从近处延伸至远处停运区 |
| 旧导览投影 | 辅助线索 | 悬在维修台上方，保留旧线路图 |
| 居民与工具 | 行为和尺度参照 | 通过操作表现空间用途 |
| 远处城市 | 背景 | 以低对比保持世界背景 |

### 13.3 本例的三个画面控制模块（示例值，不是固定要求）

以下三项只描述本例的具体选择；生成新画面时，应重新填写相应字段。

- **画幅与交付（仅用于本例）**：16:9，完整场景，像素尺寸待用途明确后选择。
- **镜头与空间（仅用于本例）**：选择广角中远景，从站台一端斜向观察，以展示车站空间及维修活动；立柱与轨道引导视线，维修台区域清楚可辨。其他任务按需求选择镜头，不固定使用广角或中远景。
- **尺度与裁切（仅用于本例）**：场景为主体，人物作为尺度参照；中央维修台及投影完整可见，不要求辨认远处人物的微小面部特征。其他任务可以以人物或道具为主体。

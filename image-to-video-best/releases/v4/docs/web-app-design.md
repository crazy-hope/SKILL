# 图生视频提示词工作台：设计草案

状态：用户已批准实施，首版本地页面与兼容接口已实现；真实模型联调待用户配置服务。验证详见 ../web/VALIDATION.md。

## 目标

用户上传一张图片，选择目标视频模型和描述等级，填写简短创作要求，获得由多模态大模型结合本项目 Skill 生成的可复制提示词。用户无需手动整理长篇结构，也无需把 Skill 文件逐个粘贴给模型。

首版建议作为本项目中的本地 Web 应用运行，面向个人使用。不自动部署、不安装技能、不直接生成视频。应用代码与已冻结的 v1 分开保存。

## 可选实现

1. 本地页面与服务端模型接口（推荐）：可以完成真实图片理解与提示词生成，密钥在本机服务端配置。需要可用的多模态 API。
2. 纯页面原型：先验证上传、表单和结果布局；只提供明确标记的演示内容，不能冒充真正的图片分析。
3. 托管应用：便于跨设备使用，但增加服务端密钥、访问控制、上传处理和部署配置；后续有需求再做。

## 页面布局

桌面端左右两栏，窄屏上下排列。

### 左栏：图片与创作要求

- 上传区：单张图片、拖放或文件选择、预览、尺寸、替换与删除。校验可解码、格式和大小；具体上限跟随选定多模态服务设置。
- 必填：目标视频模型、平台入口、一句话创意。视频模型初始包括四张模型卡中的版本；未确定入口可显式选择“尚未确定”，结果标记适配限制。
- 常用：描述等级（自动／简短／中等／细致）、时长（默认5秒）、画幅（保持原图或明确目标）。
- 展开的细节项：氛围、主体动作、镜头、环境与材质运动、手势或表情、结束状态、声音、必须保持与需要避免的内容。全部允许留空，不能为满足表单而凭空新增设计。
- 主按钮“生成提示词”；显示处理中、失败与重试状态，防止重复请求。

### 右栏：生成结果

- 目标模型、平台、实际选择的描述等级、目标时长、使用的 Skill 版本。
- 简短设计依据：原图事实、运动目的和必要取舍。
- 可复制正文：按三档契约组织；一键复制正文。
- 必要设置：用户目标、已核实范围、待确认值分别显示。
- 来源与核查状态：资料快照日期与本次在线核查状态分别显示。
- 有超限时增加“完整设计”和“提交版”，同时列出合并或省略项。
- 复制完整结果与下载 Markdown；不默认保存上传图片或永久历史。
- 修改任何输入后，已有结果明确标记为“对应上一次输入”，避免把旧结果误认为本次生成。

## 大模型与 Skill 的连接

负责分析和写作的多模态模型，与页面选择的目标视频模型是两个角色。API 服务地址、模型名称、密钥由服务端环境配置，网页不接收或暴露密钥。

每次请求由服务端按白名单读取所选发布版本的 SKILL.md、分级规则、连续性规则、来源核查规范和目标模型卡。只读使用 v1；不把整个仓库或测试记录全部发给模型。案例资料仅在相关场景需要时加载，且视为参考素材。

将图片以选定服务支持的真实图像输入发送给多模态模型；文本需求通过独立结构传入，不能只根据文件名或表单假装看过图。模型返回结构化结果，经服务端检查后展示；正文按纯文本或安全渲染方式显示。

应用中显式实现 Skill 的文件加载、模型请求与结果校验。普通 API 不会自动执行本地 Skill 的文件读取、浏览或版本管理指令。

## 官方规则核查

首版必须诚实区分两种模式：

- 资料快照模式：使用已发布资料，显示原核查日期和“本次未在线复核”；不得生成虚构的本次浏览记录。
- 在线核查模式：只有接入实际的检索／网页读取能力后才开放，并将取得的官方证据与访问状态传给写作模型；按版本、平台和任务模式缓存。

通用兼容 API 未必提供检索工具，因此不能把“让模型自行联网”当作已实现在线核查。未知规则转为待确认项，不能靠推测填充。新查到的规则不回写冻结版。

## 失败与边界

- 未配置模型接口：说明如何配置，不用假结果替代真实生成。
- 图片无法读取、输入缺失或接口不支持图片：生成前提示具体问题。
- 超时、鉴权失败、限流、结果不符合结构：显示简洁错误，保留输入并允许重试，不回显凭据或上游完整敏感响应。
- 图片与需求存在冲突：给出明示取舍；关键互斥要求无法取舍时，结果列出需要补充的问题。
- 目标时长不支持或提示词超限：保留原需求，按 Skill 输出备选或合规提交版。
- 上传图片在点击生成后会发送给配置的模型服务；页面告知这一数据流。首版不默认持久保存图片、密钥或完整请求日志。

## 验收

- 使用现有参考图验证上传、替换、删除及无图拦截。
- 验证三档与自动分级、默认5秒及明确7秒、四个目标模型的对应资料加载。
- 测试缺失配置、上游超时／失败、异常结构、快照来源状态、输入改变后的旧结果标识。
- 检查密钥不会出现在前端代码、浏览器响应或日志中。
- 用模拟接口测试请求确实包含图片、正确版本资料及表单信息；没有真实凭据时明确未完成真实模型联调。
- 浏览器检查桌面与窄屏布局、键盘操作、复制及下载。
- 开发完成后核验 v1 原始校验和，证明未修改已发布技能。

## 已确定的接口方案

用户选择兼容 OpenAI 的多模态服务，地址与模型可配置。首版按 Chat Completions 的文本与 image_url 内容格式适配，使用服务端配置的 API 根地址、模型名称及密钥。兼容该接口不保证兼容所有可选参数，首版不强制服务商支持 JSON schema、联网或工具调用。

服务端要求模型返回约定 JSON，并检查结果结构；返回错误或截断时提供明确失败信息，不把未经解析的任意文本假装成合规结果。没有真实服务配置时可以运行页面和模拟接口测试，但不宣称完成真实模型联调。

官方接口依据（2026-10-17读取）：[Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)、[图片输入](https://developers.openai.com/api/docs/guides/images-vision)。第三方服务的实际图片能力、格式及限制仍由用户配置的服务决定。

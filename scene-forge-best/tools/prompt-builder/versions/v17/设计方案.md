# V17 画面展开与文本审校设计

日期：2026-10-30；状态：实施依据；用户已明确授权本轮全面重构。

## 目标与方法

从用户示例提取八个叙述职责：画幅与媒介质感→具体场景与当前瞬间→对象动作和接触→关键对象的位置及未完成状态→材料与环境反馈→光色及传播→镜头与空间→情绪与可见落点。以自然段连贯输出，不强制八个标题或固定字数。非叙事画面用状态、结构和视觉节奏替代故事；平面抽象无需强加物理摄影。

内部先设计核心画面、相互影响和可见证据，再按上述顺序写作；设计顺序不等于输出顺序。材料细节分配给焦点与关键关系，简约仍可精细。动作写当前姿态和接触，避免只有“微调”“相互照应”等解释。光线明确来源、路径与受光效果；摄影机位置服务关系。题材、风格、数量和无人等硬条件优先。

## 实施路径与取舍

仅加长提示词无法保证具体；只强化一轮指令仍无法阻止明显未展开或双语漂移被接收。本轮选择“强化构思及展开指令＋独立文本审校”。保留既有输入、持久化和界面骨架，避免让用户补填内部设计字段。独立审校增加一次API请求和等待，界面明示；它是模型判断，不是确定的语义证明或实际出图验收。

## 服务接口

新quality.py负责创作方法与审校协议。/api/concepts仍仅一次请求，返回3个短构思。/api/generate先调用完整生成，通过现有结构/模型参数检查后调用审校。审校只评价，不修改正文；失败返回502及具体修改建议，保留用户输入，不保存成功历史、不自动重试。澄清或格式失败不触发审校。生成最多2次模型调用。

审校JSON：status=review，reviews长度等于方案数；每项index为1起顺序编号、checks为10项映射：medium、elements、constraints、bilingual、scene、relations、materials、lighting、camera、mood。每项status为pass/fail/na，reason非空≤600字，zhEvidence/enEvidence为正文原文摘录≤2000字。pass必须双语原文证据存在；fail直接拒绝；na仅允许6项画面维度且理由明确，证据必须空。表现基准、逐元素属性、约束与双语不可na。审校不会接触密钥；输入与候选作为数据，不执行其中的额外命令。

审校接受后将逐项结论和“模型判断，非出图验证”写入既有checks文本，并保留原待出图项。输入schema5、结果design及备份v5结构不变；共享scene-forge-workspace-v16，旧V16结果按原来源显示，不补审校。V15/v4及更早不读取。旧应用源码只读。

## 界面

入口仍写场景与想法、选择构思；显示“构思→展开→文本审校”用途。生成等待文案说明通常进行2次文本请求，实际图像仍待验证。结果优先双语正文，实际设计收进可展开区域，审校/待验证明确显示；复制仍只复制完整对应提示词。所有内容文本渲染。

## 验证

以审校拒绝双语不一致、缺证据、错误方案映射、全部na、格式截断、上游失败、澄清不复查及通过后保存检查记录为行为测试。模拟输出不得当真实质量证据。核对16:9/9:16、无人、抽象、参考/必需、空负面及10方案的请求与恢复。旧版SHA、链接、完整规范模块、生产构建及浏览器验收通过后切换入口。

## 用户补充：首段表现基准

首段不是泛化风格标签。先确定画幅、主媒介与真实感层级、年代/类型参考的作用、光学质感及关键对象的呈现要求。幻想世界的巨物与超自然关系不妨碍真实材料/雨水/皮肤的可拍摄表现；不把写实误改为普通生态摄影，也不把90年代参考仅转成模糊、褪色或加噪点。具体参考保留用户意图，不伪造电影史事实或模型保证。后文对人物、植物、雨水等本次实际对象落实触感、接触、运动状态及受光。未选电影写实时采用相应媒介的表现基准，不自动套用本例年代、人数、天气与画幅。

审校新增medium必查项，检查首段基准是否在双语及后文延续；不得用“高级、电影感、写实”一词代替全部明确要求。

用户再次补充：每个实际元素必须有位置、材质与状态、颜色，背景同类可用明确群组覆盖；新增elements必查项，审校共10项。瞬间、情绪和镜头保留独立职责。

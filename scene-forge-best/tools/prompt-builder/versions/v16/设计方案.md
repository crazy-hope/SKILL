# 场景构思工作台 V16 设计

日期：2026-10-30；实施设计。用户已授权上一轮提出的方向，以下未由用户逐项指定的细节为实施选择。

## 目标与方案

采用场景中心的两阶段流程。比较：仅折叠旧表单成本低但不能让人先判断创意；预设固定画面便捷但容易重复；先短构思再展开能让用户选择关系与空间后精修，采用第三种。保持现有React、Ant Design、Vite与Python服务，复用现有依赖。

日常入口突出“核心场景”和“想法”；只填想法也能开始。荷塘为第一组可点击参考方向，点击明确设置荷塘核心与背景及方向，可取消或自定义；方向描述不隐式指定人物、天气、比例或服饰。精修保留十维顺序、元素参考/必须、人物与关系、负面实际输入值，支持保持不变与允许变化的可选文字。负面空值继续表示无负面。

第1步按当前输入请求3条短构思，分别呈现标题、画面、关键关系和差异；不得输出伪造的双语成品。第2步选中一条，将其保存至草稿。第3步将选中核心关系展开为用户数量指定的1—10对完整双语，保留完整design与模型适配。每个方案围绕选中构思改变相容的动作细节、空间组织与视点，不能另换核心世界或角色关系。

创作内容变化清除当前候选和选中构思，需重新构思；延迟旧响应不覆盖修改后的输入。失败或澄清保留输入，可重试；历史查看和复用保持明确。选中构思可刷新恢复，候选短构思仅当前页面保存。旧最终结果仍可查看，不能被误认为对应当前新输入。

## 数据与接口（前后端共同契约）

新输入schemaVersion=5，保留原FIELDS/地域/elementSettings/designOptions，新增必填scene：

```json
{"core":"","backdrop":"","direction":"","keep":"","change":"","selected":null}
```

五个字符串各最多1000字。selected为null或恰含title/summary/relationship/variation的对象，各为1—1000字非空字符串。所有这些信息均保存和导出。scene.core限定核心场所；backdrop限定陪衬；direction为选中的探索方向；keep是明确保持项；change是允许变化项，不覆盖其他硬条件。主次不等于画面占比。

POST /api/concepts：{provider,model,key,brief} → {status:"concepts",concepts:[{title,summary,relationship,variation}×3],brief,spec,provider,model}，或原clarification格式。完整规范和所有输入约束传入两阶段。概念结构严格校验、三条不得完全重复，不生成本地伪创意。

POST /api/generate沿用原格式，但要求brief.scene.selected有效，返回ready/schemes及原provenance；数量仍读取brief.数量。未选择时在调用上游前拒绝。目标模型分支仍来自完整规范登记；多家族硬冲突保持clarification。

schema5、scene-forge-backup-v5、scene-forge-workspace-v16独立于旧版；不迁移v4。独立接口配置与密钥项沿用。密钥不进入日志、快照、备份、下载。

# 工作台 V13 设计方案

日期：2026-10-25。依据[需求](需求.md)。

## 技术选择

采用React + Ant Design + Vite，保持Python标准库后端。Ant Design具备中文本地化、选择器、表单、抽屉、弹窗与主题配置，适合现有密集创作表单。比较方案：手工组合headless组件需要重新实现更多表单交互；全栈框架增加当前本地单页不需要的路由和服务层。UI库由用户授权助手选择，未将其记为用户指定品牌。

官方资料（2026-10-25）：[Ant Design介绍](https://ant.design/docs/react/introduce/)、[Vite集成](https://ant.design/docs/react/use-with-vite/)、[Vite指南](https://vite.dev/guide/)。实际依赖版本锁定在package-lock.json。

## 页面与交互

浅暖灰背景、深灰文字、低饱和绿色主操作。顶部品牌/当前规范/记录/接口配置；紧凑介绍与独立负面输入；预设工具栏；桌面五列两行十面板，卡片内部滚动；底部中央生成。窄屏自动变为两列或单列，生成按钮持续可用。

题材/元素用可搜索分类抽屉和自定义输入；卡片保留所选项，元素可进入属性抽屉。其余选择用Ant Design控件，允许自定义，空值与默认语义不变。地域再次点击取消。负面和说明可明确清空。

结果Modal保留左侧方案标题与右侧完整输入、双语正文和来源，两个区域独立滚动。首次展示无剪贴板副作用；点击标题才复制英文。错误/澄清不记成功历史。配置、记录、预设命名使用统一Drawer/Modal，模型文本直接作为React文本渲染。

## 数据与实现

保留brief.mjs、core.mjs、catalog.mjs的业务规则，React组件不再依赖原form.mjs或app.js的DOM操作。workspace.mjs负责白名单持久化与备份；React hook持有草稿、预设、历史、provider/profiles；独立credentials.mjs只处理API Key。沿用scene-forge-workspace-v12及scene-forge-api-keys-v1，schemaVersion=3、scene-forge-backup-v3；V11及更早数据仍不读取。损坏存储不静默覆盖。

Python读取完整规范V10，仅公开dist静态资源与既有API；保留Host/Origin/token验证和禁止脚本内联的CSP，为Ant Design运行时样式调整样式策略。dist随版本交付，根启动器直接运行Python；开发时才需要npm。

## 验证与限制

先验证V12基线，再增加存储/导出/React交互和静态服务回归。浏览器用明确标记的模拟响应核验十方案、剪贴板、备份、下载、刷新与窄屏；不用真实密钥或付费接口。历史文件SHA与题材库逐字比较。实际模型与出图遵守度不在本轮验收范围。

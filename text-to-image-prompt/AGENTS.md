# 维护约定

用户要求每次大改都区分版本：v1、v2、v3。维护本项目时先读 `CHANGELOG.md`，以根目录 `SKILL.md` 的 `metadata.version` 为当前版本。

- 交互阶段、默认输出结构或创作行为的大改：递增整数版本；修改前确认旧版已有完整快照。
- 已发布的 `releases/vN.zip` 不覆盖。小修沿用主版本并在 CHANGELOG 中追加记录；需要归档时使用唯一的 `vN-fixK.zip`。
- 每个发布包包含 `text-to-image-prompt/SKILL.md`、`agents/`、`references/`；不包含历史发布包或测试记录。
- 当前工作目录、当前版本快照与已安装 skill 的运行文件须保持一致。只同步运行文件到技能安装目录，避免安装历史技能副本。
- 验证既检查格式，也检查实际对话是否停在用户选择环节、换一批是否保留条件、两个变化方式是否遵守不同约束、中英文详细版本是否一致。
- v3 起每次只询问一个设置项目，文化背景与内容现实性须单独确认；电影实拍不自动授权幻想内容。测试应覆盖逐项提问、用户主动一次回答多项、现实内容与摄影质感的区别。
- v3 修订1按用户要求保持 v3，新增独立的具体视觉风格选择，使用 `v3-fix1.zip` 保存。以最新版本或修订包核对运行文件，历史包不覆盖。
- 不把提示词或对话测试称为 Midjourney 生图效果验证。
- v4 起优先原生选择／输入提问，每次一个问题；验证异步 accepted 不推进、自由输入被接收、场景编号映射和工具不可用回退。测试使用模拟工具时明确标注，不能声称实际客户端弹窗已端到端通过。
- v5 起八项逐问；题材及两类风格均可多选融合，电影与纪实分开，具体年代须有用户选择来源。验证单选卡片上的组合输入／逐次追加及所有已选方向在成品中保留。

## 配套工作台同步

- `workbench/` 是独立版本的 React 本地工作台；skill 版本与工作台版本分别记录，不因工作台开发修改 skill 运行规则或覆盖历史发布包。
- 修改 `SKILL.md` 或 `references/` 时，必须检查是否影响工作台的字段、选项、流程、输出结构和参数处理；有影响时在同一次维护中更新工作台，不只替换源文件指纹。
- 工作台每次生成读取项目源文件。`workbench/skill-manifest.json` 表示已核对的运行来源；变化后先审查差异、更新界面/流程和回归测试，再更新 manifest，运行 `cd workbench && npm run check`。
- 新增或调整生成依赖的参考文件时，同步 `server/rules.ts` 的来源列表、manifest 与字段出处。未同步期间阻止新生成，保留草稿与历史可读。
- 工作台密钥只存在被忽略的 `.local/`；不将其加入 Git、发布包、测试记录、日志、历史或导出。skill 发布包继续只包含既有运行文件，不包含工作台。
- 界面适配是用户明确授权的集中面板，不反向修改 skill 原有逐问流程。验证注明真实浏览器、模拟 HTTP、真实大模型联调各自范围，不把文本检查称为生图效果验证。

- v7 九项设置，在具体视觉风格之后独立确认整体色彩／色调；每段中英成品显式概括整体调色，工作台包含对应字段，旧设置缺项补选而不默认代选。

- 当前 v8 十项设置，在内容现实性之后独立确认可多选的情绪／氛围；全部候选和中英成品保留选择并用可见细节支撑，不由情绪推导色调、天气或爱情关系。工作台保留既有结构化成品格式。

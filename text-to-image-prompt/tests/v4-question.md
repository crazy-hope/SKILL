# v4 原生提问行为模拟测试

范围：只读根目录 SKILL.md；未修改项目、未实际调用原生提问工具、未向用户展示测试弹窗、未生图。这是按技能执行的模拟调用与行为评估，不是实际客户端 UI 端到端测试，也不是 Midjourney 生图效果验证。

模拟能力 A：Default 模式可用 `functions.request_user_input_async`，schema 为 `{questions:[{title:string,options?:string[]}]}`，允许自由文本，首项可预选但不会自动提交；调用响应为 `{accepted:true}`。`request_user_input` 仅 Plan 可用，本测试不会调用它。每次调用只有一个问题。

## 1. 用户：今天没灵感

计划调用：`functions.request_user_input_async`

```json
{"questions":[{"title":"画面想用哪种表现风格？这项决定画面怎么表现，是否允许非现实事物会单独确认；也可以直接输入你的偏好。","options":["电影实拍／纪实摄影（真人外观、自然皮肤与真实材质光线）","插画","油画","动画／卡通","微缩模型","自由选择"]}]}
```

模拟响应：

```json
{"accepted":true}
```

后续行为：保留第一项“表现风格”待答。不要求用户先提供主题，不提供五场景，不问下一设置，不交付提示词。正文不重复问卷；本轮结束，必要时仅说“请在提问卡片中选择或直接输入”。自由输入由工具提供，不额外添加“其他／自定义”选项。

评估：通过。选择工具符合当前模式，问题数量为一，风格与内容现实性分离。

## 2. 工具已回 accepted，用户未答

计划工具调用：无。

响应处理：`accepted` 只记录问题已展示，不能记录任何用户选择。第一项即使预选也没有提交；空答、关闭、时间流逝不触发默认答案。不会换成文字问卷，不重复发卡，不推进。

本轮可用结束语：“请在提问卡片中选择或直接输入。”

评估：通过。没有把异步接受误作回答；也没有把未回答误作工具失败。

## 3. 用户自由输入：粉彩纸感插画

记录：大类风格＝插画；具体视觉风格＝粉彩纸感。用户一句话已提供两项，不重新要求选择大类，也不再询问具体视觉风格。下一个缺项为文化背景。

计划调用：`functions.request_user_input_async`

```json
{"questions":[{"title":"这轮场景希望偏东方还是西方？也可以直接输入具体地区、时代，或说明没有文化指向。","options":["东方","西方","东西融合","自由选择","无文化指向"]}]}
```

模拟响应：

```json
{"accepted":true}
```

后续行为：文化背景待答，停在此处。不会把“粉彩纸感”推断为西方、幻想或某一画幅。用户后续回答文化后，下一缺项才是内容现实性。

评估：通过。自由输入被识别，已回答项跳过，下一次仅问一个缺项。

## 4. 全部设置确认，五个完整短构思已展示

输入标题顺序：1 书摊收帘，2 桥边递伞，3 院内移盆，4 门口接箱，5 窗边补灯。题设认为完整短构思已展示，因此本次不重复正文。

计划调用：`functions.request_user_input_async`

```json
{"questions":[{"title":"想继续哪一个场景？也可以直接输入编号或修改意见。","options":["1 书摊收帘","2 桥边递伞","3 院内移盆","4 门口接箱","5 窗边补灯","换一批"]}]}
```

模拟响应：

```json
{"accepted":true}
```

后续行为：场景待答。映射固定为本批次的 1→书摊收帘、2→桥边递伞、3→院内移盆、4→门口接箱、5→窗边补灯，不根据语义相近程度重新匹配编号。

补充映射探针：模拟用户随后输入“3”，记录“院内移盆”为已选场景，下一步仅问变化方式：

```json
{"questions":[{"title":"想怎样变化“院内移盆”？前者保留同一动作与道具状态，只改机位和构图；后者保留同一场景与人物，改变具体互动和动作。","options":["同一瞬间、不同拍法","同一场景、不同故事瞬间"]}]}
```

此调用同样在 `accepted` 后等待，不直接生成三版。

评估：通过。五候选没有丢失，额外提供换一批；编号对应正确；选定场景后仍尊重变化方式选择。

## 5. 用户：换一批

状态处理：保留用户所有硬条件以及已确认的七项设置。若原设置允许自由选择，保留其已确认范围。清除旧场景选择；不重新开启七项问答。对照可见历史，避免重复收帘、递伞、移盆、接箱、补灯的核心事件。不自动生成第二轮之后的更多批次。

先输出新的五个完整短构思，再调用一个选择问题。题设未给出全部设置和硬条件的具体值，因此以下仅是编号映射的测试标题，不声称已验证新构思与未知设置的内容一致性：1 巷口寻猫、2 窄门让琴、3 长桌铺布、4 台阶系鞋、5 走廊扶画。实际创作必须先按真实保存的条件设计每条构思的地点、事件、互动、看点与风格体现。

计划调用（映射夹具）：`functions.request_user_input_async`

```json
{"questions":[{"title":"这批想继续哪一个场景？也可以直接输入编号或修改意见。","options":["1 巷口寻猫","2 窄门让琴","3 长桌铺布","4 台阶系鞋","5 走廊扶画","换一批"]}]}
```

模拟响应：

```json
{"accepted":true}
```

映射探针：新批次展示后，用户输入“3”应选“长桌铺布”，不能选旧批次的“院内移盆”。明确说“上一批的3”才解析为旧批次场景；若引用不清晰，只问一个澄清问题。新场景选定后重新询问变化方式，除非用户明确要求保留原方式。

评估：流程与编号映射通过。因为输入未包含完整七项具体值与硬条件，本项没有进行完整新场景内容合规测试；保留状态是模拟行为，不是已运行的程序断言。

评估：通过。无选项的自由文本问题符合模拟 schema；仅补当前缺项。

## 发现与结论

在指定的模拟能力 A 下，SKILL.md 能导出合法的单问题 JSON，并明确约束 accepted、自由输入、当前批次编号映射、缺代码输入与工具不可用回退。上述七个用例未发现技能文本中的明确阻断或冲突。

本报告是手工执行的模拟调用与状态推演。没有测试真实工具 schema 是否与模拟一致、客户端是否显示卡片、预选行为是否如假设、自由文本是否能从真实 UI 回传，也没有确认真实客户端端到端通过。第五项缺少真实设置值，因而只验证流程与映射设计，没有声称完整新场景内容测试通过。

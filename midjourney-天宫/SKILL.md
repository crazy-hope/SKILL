# Midjourney 东方天界巨构导演

## 核心原则

从文字建立原创画面，并让随机变化服从同一视觉语法：

> 一个连续且延伸出画框的主视觉巨构或尺度主体 + 一个大面积空明天域 + 一套清楚的主辅构图 + 一个可选且真实落位的尺度锚点 + 一组有明确空间关系的电影镜头 + 冷环境中的少量方向性暖光。

建筑与人物都不是必选元素。用户选择 `F1-6 无建筑` 时，不得为满足旧有巨构语法自动补入宫殿、楼阁、亭台、塔楼或屋顶；由已选天界结构、地形、自然奇观或自定义主体承担主视觉尺度。用户选择 `F2-4 无人物` 时，不得自动补入人物，改用结构重复、纹理尺度或其他已选锚点证明体量。

人物一旦出现，只能用来作为空间尺度标记，不承担叙事主体或视觉焦点。人物出现时必须保留“古风仙者/古代衣袍/背影”识别锚点，不得使用现代人物语义。仙女头型规则继续保留，但只在人物局部编辑、用户明确要求人物可辨或选择 `C18 肩后构图 OTS` 时展开，避免发型细节诱导 Midjourney 放大人物。

人物尺度只用空间关系表达，不在锁定卡、中文提示词、英文提示词或模板中使用画面高度百分比、像素高度、数值比例或大小人物对照。默认或用户要求单人时，全画面只有一名仙者；用同一句话写清这名人物的古风身份、极小远景尺度、背影和唯一承载位置，不再另写一个近景人物或第二个尺度标记。只有用户明确要求多人时才按指定人数生成；`C18` 仍只表现同一名人物，不另补远景分身。

随机只改变未锁定的空间组合，不能随机掉以上关系。用户明确条件优先；未指定项先进入选项问卷，不直接套用默认。朝代名称只作为幻想建筑的视觉线索，不声称考据复原。

“巨构压迫感、震撼、宏大”只描述尺度关系，不自动切换为暗色、冷峻或低曝光模式。默认只在用户选择“默认/推荐”或明确要求跳过询问时使用；随机只作用于用户标记为随机的模块。

构图目录包含基础构图与用户可明确选择的高级复合构图。`C18 肩后构图`、`C24 鸟瞰`、`C25 上帝视角`、`C27 极端留白`、`C35 鱼眼式构图` 等会覆盖与其直接冲突的默认人物尺度、相机依托、留白比例或低畸变倾向，但不覆盖用户在其他模块中的明确选择；真实冲突仍进入询问。

## 交互入口

每次使用本 Skill，先完整读取[缺项问卷](references/interactive-questionnaire.md)。在生成提示词前解析六个模块：已指定项直接锁定，只对未指定项以纯文本完整列出固定选项并等待用户输入编号。不要使用按钮、可视化问卷或外部选择器。除非六个模块均已确定，或用户明确说“全部默认、全部随机、其余推荐、不要问、直接生成”等跳过口令，否则本轮不能生成最终提示词。

## 六维路由

每次创建、改写或批量编写提示词，按顺序读取并应用：

1. [风格](references/style.md)
2. [画幅](references/aspect-ratio.md)
3. [构图](references/composition.md)
4. [镜头](references/camera.md)
5. [光线色彩模式](references/light-and-color.md)
6. [元素](references/elements.md)

优先级始终是：`用户明确要求 > 系列锁定 > 本 Skill 默认 > 随机选择`。不同维度冲突时，保留用户条件，并重选兼容项；只有用户条件本身互相矛盾时才询问。

## 默认候选

只有用户选择默认/推荐或跳过询问时，才应用以下内容：

- 风格：电影级写实东方神话环境 CG，庄严、静谧、超现实但结构可信。
- 画幅：`16:9`。
- 构图：留白构图为主，三分构图为辅；巨构位于一侧，另一侧保留空明天域。
- 镜头：相机位于建筑内部或可行走边缘，中等广角、低畸变、深景深；近景巨构被裁切并延伸出画框。
- 光色：明亮仙境；天青冷环境、朱红或深木建筑、左上方暖金清晨斜光、正常曝光。
- 元素：默认是一座连续中国宫廷巨构、平整云海和一名性别不强调的成年背影仙者，但建筑与人物均可明确选择为无；墙面系统与其他奇观不自动加入。摆放方式在用户选择推荐/默认或跳过询问时使用 `F5-1`，按九宫格参考兼容随机。

## 工作流程

1. 按缺项问卷进入 `ASK`、`WAIT`、`ASK_REMAINING` 或 `GENERATE`。问卷回合只提问并停止，不能提前给提示词。
2. 进入 `GENERATE` 后，建立“六维锁定卡”，记录用户指定项、选择项、默认项和受控随机项。
3. 先锁定主视觉尺度主体、开放天域、主辅构图、镜头物理站位及整批色光；存在人物时再锁定人物尺度。随后从元素库中选择有限的从属元素，并按 `F5` 摆放模式确定每个可见元素的位置。
4. 批量任务整批固定风格、画幅、主主体类型、色彩家族、光向和曝光；存在建筑时固定建筑体系或朝代，存在人物时固定人物数量、性别策略和尺度。用户要求构图随机时，逐张登记主辅构图，兼容主构图用尽前不重复；鸟瞰、上帝视角、鱼眼、不可能透视和上下颠倒等明确选择型构图不进入普通随机池。每张至少改变镜头所在空间、观看方向、主主体方向、开放区位置四项中的三项；此要求针对相邻画面，兼容镜头用尽前不重复。只有用户明确要求相应锁定维度随图变化时才解除锁定。
5. 按以下顺序先建立一份语言无关的场景关系，再分别写成中文提示词和英文提示词：
   `风格身份 → 画幅行为 → 主辅构图关系 → 镜头物理关系 → 主视觉主体及可选朝代线索 → 开放天域 → 已选人物、其他元素及其画面位置 → 光线色彩 → 材质与气氛`。
6. 中英文两份提示词必须描述完全相同的构图、镜头、元素位置、光色和材质，不能各自随机。参数必须位于两份提示词末尾并保持一致。默认使用 `--ar 16:9 --raw --s 450 --c 8`；画幅替换为用户选择，单次必须给出具体数值，不能输出数值范围。用户指定参数时服从用户；不自动写死模型版本。
7. `--no` 只列当前最危险的简单对象词，例如 `neon, cyberpunk, skyscraper, text, logo, watermark`。先用正向关系控制画面，不用长串负面词代替构图。

## 标准输出

### 问卷回合

只输出纯文本问卷：显示已锁定摘要，并在每个缺失模块内完整列出全部固定选项、随机入口和回复示例，由用户手动输入编号。`B1 16:9` 必须标记为默认推荐。输出后停止，不生成提示词。

### 生成回合

六个模块确定后，除非用户要求简洁，只输出：

1. `六维锁定卡`：风格、画幅、构图、镜头、光线色彩、元素。
2. `中文提示词`：一个可直接复制的代码块，使用中文视觉描述并在末尾放置参数。
3. `English Prompt`：一个可直接复制的代码块，使用英文视觉描述并在末尾放置与中文版完全相同的参数。
4. `变化说明`：仅用于随机或批量任务，说明整批锁定项和逐张变化项。

默认始终输出中英文两份；只有用户明确说“只要中文”或“只要英文”时才输出单一语言。用户要求“只要提示词”且同时表示直接生成或已经提供全部模块时，不输出锁定卡与解释，但仍输出中英文两份提示词。仅说“只要提示词”本身视为跳过询问。没有可用的 Midjourney 提交工具时，只交付提示词，不声称已经生成图片。

## 交付审计

- 第一眼是否是一个连续的主视觉尺度主体，而非许多等大的独立对象？选择无建筑时，是否完全没有自动补入宫殿、楼阁、亭台、塔楼或屋顶？
- 是否同时存在局部高密度结构和内容承载空气？常规构图开放域约占 `40%–60%`；明确选择 `C27 极端留白` 时为 `80%–95%`。
- 是否明确一个主构图和最多一个辅助构图，并写成可见关系而非标签堆叠？
- 若存在未指定模块，是否先完整显示缺失模块的全部固定选项并停止，而不是直接生成？
- 问卷是否使用纯文本完整列出缺失模块内的全部固定选项，并让用户手动输入编号？
- 相机是否有明确站位和观看方向？除 `D22`、`D27`、`D28` 外是否存在被裁切的近景构件；空中镜头是否严格服从各自的轻俯远望、鸟瞰或垂直俯视定义？
- 若选择人物，是否同时写出“仙者/古风背影/古代衣袍”身份锚点（不展示面部），常规人物是否为被巨构衬得极其渺小的远景身影、面部不可辨，并站在可承载平面上？是否已删除人物尺度的百分比、像素高度和数值比例？单人场景是否全画面只有一名人物，且身份、尺度与位置集中描述，没有额外的大人物、近景人物或重复身影？除人物局部编辑、用户明确要求人物可辨或 `C18 肩后构图` 外，是否没有展开仙女头型细节？使用 `C18` 时，是否只展示同一名人物的肩背轮廓，没有另补远景分身或变成人物海报？随机摆放时是否允许人物落在画面中段，而非总在底部？若选择无人物，是否完全没有补入人物或人物承载句？
- 是否只加入用户指定或元素预算允许的内容，没有自动堆满天环、浮山、瀑布、天梯和体积光？
- `F1-7`、`F2-6`、`F3-4`、`F4-25` 或 `F5-2` 是否都附有必需的自定义文本，且每个元素子项的自定义入口仍保持在末位？
- 若选择墙面，是否已经落实墙体厚度、材质、空间位置和物理依附？云墙是否保持局部连续而非棉花云堆，水墙是否具有水源、垂落方向和落点？
- 是否已经确定 `F5` 摆放方式，并将每个选中元素的位置写成与构图、镜头和物理承载兼容的可见关系？
- 色光是否统一、暖色覆盖克制、暗部可读、云层不过曝？
- “冷青柱光”是否落在承重柱材质关系上，而不是蓝色柱状体积光？
- 中英文提示词是否表达完全相同的构图、镜头、元素位置、光色和材质，而不是分别随机？
- 两份提示词的参数是否全部位于末尾、彼此一致，且 `--ar` 使用整数比例？

任一核心项失败时先修提示词，再交付。

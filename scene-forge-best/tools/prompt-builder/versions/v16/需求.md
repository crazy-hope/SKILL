# 工作台 V16：围绕场景构思

日期：2026-10-30；状态：已交付；记录方式：事前记录。
基线：[工作台V15](../v15/README.md)、[规范V13](../../../../versions/v13/输出/规范框架v13.md)。

用户认为当前工作台过于复杂、随机而单一，希望每个题材聚焦两三个具体场景，以田野荷塘为核心，发展荷上休息、荷下避雨或乘凉、荷间泛舟等有关系的画面。助手建议先以荷塘试行“构思场景→选择构思→完整双语”，细节进入精修，支持自定义场景。用户回复“好，你开始重构吧”，中断后要求“继续”。这授权实施上述方向，不冒称用户确认了本文件每项技术选择。

| 编号 | 要求 | 验收条件 |
|---|---|---|
| R-01 | 简化日常创作入口 | 核心场景与想法为主；十维细节、负面进入可展开精修；无额外必填长表 |
| R-02 | 荷塘首组场景及通用创作 | 荷上小憩、荷下庇护、荷间泛舟三个方向可选可取消；支持自定义核心场景，不把古镇提升为中心，不向其他题材注入荷塘或仙女 |
| R-03 | 两阶段真实请求 | 先请求3条短构思，选择一条后请求1—10对完整双语；概念阶段不冒充最终提示词；修改创作内容后旧构思失效 |
| R-04 | 有边界的创意 | 核心场景和明确要求保持；差异来自动作、对象关系、空间及其可见后果；保持/变化补充可选；文化、无人及必需关系继续生效 |
| R-05 | 完整数据与旧版保护 | schema5、backup-v5、workspace-v16，选中构思随草稿、预设、历史、备份及下载；旧版不读取迁移或覆盖；独立密钥沿用 |
| R-06 | 完整规范与交付 | 完整规范V14、V16源码及dist、根入口同步；真实模型与图像效果未执行则明确记录 |
| R-07 | 验证与异常保护 | 前后端严格校验、双服务模拟、失败重试、刷新、失效构思、损坏存储、桌面手机流程验证 |

实施选择：首轮只精编荷塘三方向，其余题材保留在精修中并支持自定义场景；核心场景默认空，不自动加入人物；数量沿用5条，表示选中构思展开的双语方案数，构思数量固定3。无收费模型调用、出图、安装依赖或Git提交。

预期成果：[设计方案](设计方案.md)、[计划](计划.md)、源码输出、变更、验收、README及规范V14。

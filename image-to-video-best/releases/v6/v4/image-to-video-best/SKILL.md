# 图生视频提示词导演

读懂首帧，为目标模型写出具体、连贯、可执行的运动设计。描述深度由氛围与控制需求决定，不以越短越好或越长越好评价提示词。默认中文、5 秒、一个连续镜头；用户的语言、时长、动作、等级和声音选择优先。本技能只交付设计与提示词，不调用视频生成服务。

默认正文按[六段结构](references/prompt-structure.md)输出：**全局基础硬性设定 → 场景基底 → 主体动态细节 → 运镜规则 → 同期环境音效 → 硬性约束**。三档保持这套结构；用户明确要单行时按同一逻辑顺序合并，等级不随排版降低。

## 输入与分级

1. 实际查看图片，先按[画面、题材与融合分析](references/visual-analysis.md)识别内容与关键元素，分别判断题材/世界观、表现画风和情绪氛围，支持多种题材融合。区分可见事实、推断、无法确认的区域、用户要求的新增设计。缺图且无文字场景时，请求图片或文字描述；只有用户明确选择文字场景设计时才据此写作，并注明未查看首帧。
2. 确认准确模型版本与任务模式：首帧、首尾帧或参考生成。没有目标模型时先询问；可并行做通用画面分析，但不冒充已完成模型适配。用户明确只要通用版时直接提供，并标记“未做模型适配”。
3. 网页为主，API 按需。仅称“网页”不足以确定即梦、方舟、Dreamina、第三方聚合平台等入口；只有差异影响引用语法、参数或能力时才追问具体入口。未确认时可给模型层面的正文和待核实设置，不虚构按钮或 API 字段。
4. 用户指定等级优先；否则依据下表选择，在交付中用一句话说明原因。完整操作见[三档写作](references/levels.md)。

| 等级 | 判断依据 | 正文形态 |
|---|---|---|
| 简短 | 一个主要变化，运动与观看目的明确 | 六段各用短句，保留动作、镜头、必要环境与结束状态 |
| 中等 | 主体、环境、运镜需要配合，有少量局部或材质控制 | 六段展开主体、环境、镜头与关键关系 |
| 细致 | 多阶段动作、精细手势、持续流体、复杂遮挡或音画同步 | 六段充分展开局部、材质光影、时序、持续环境、声音与约束 |

安静不等于简短，热闹不等于细致；“分析说明简短”也不等于“提示词正文必须简短”。不设置跨模型统一字数上限。

## 核对目标规则

先读[来源与模型核查](references/model-verification.md)，再只加载目标资料：

- [Seedance 2.0](references/models/seedance-2.0.md)
- [Seedance 2.5](references/models/seedance-2.5.md)
- [Runway Gen-4.5](references/models/runway-gen4.5.md)
- [Wan 3.0](references/models/wan-3.0.md)
- [可灵 VIDEO 3.0 Omni／用户称O3](references/models/kling-video-3.0-omni.md)：需核对实际入口，不混用普通3.0、O1或第三方字段。

同一会话首次使用目标版本与平台时，通过可用浏览工具核查官方页面。复用本会话核查结果；版本、平台或任务改变时重新核查相关规则。区分硬性限制、官方建议、导演默认值。网页支持情况不能从 API 字段反推。未知型号核实后再适配，不能偷偷换成已知型号。

无法联网时，使用明确标明日期和入口范围的资料快照，并说明本次未在线复核；资料未覆盖的能力保持未知。正文、负面段落、独立负面字段是不同概念，按目标入口支持情况输出。

## 保留用户动作与细致表达

先读取[创意保真与细致展开](references/creative-fidelity.md)。合并一句话需求与细节字段，识别用户指定的动作、方向、速度、先后、结束景别、材质与氛围；按首帧补全实施路径，不替换这些选择。

细致档围绕用户的视觉重点展开材质外观、分层运动、主体联动、持续性、遮挡、光影氛围和镜头时序。分析说明可短，提示词正文仍须充分展开；“衣袂流动、氛围梦幻”不能代替这些具体控制。阶段设计不得擅自加速、换动作或挪用参考案例的编舞。

## 导演设计

将画面分析转成具体设计：每个重要元素的材质、运动、光影和保持项都来自该图与用户要求。“梦幻”“卡通”“东方幻想”“赛博朋克”不作互斥选项，融合须说明各自对应哪些元素；不靠单一霓虹色或云雾断定题材，不将流体神女、真人胶片或快速故障效果作为通用模板。完整方法见[画面、题材与融合分析](references/visual-analysis.md)。

用户只有图片并希望自动设计时，不要求其先选择题材或编好动作；根据可见姿态、空间、材质与氛围提出合适的动作、环境、镜头和收尾，标明是设计建议。有明确要求时以用户要求为准。默认交付一个完整主方案；用户要求多个方向或存在有意义的不同观看重点时，可给少量独立候选，每套保持图像锚点并说明设计区别。目标模型未知时可先给通用方案并询问模型，不虚构适配结论。

先按[场景关系与动态](references/scene-direction.md)区分视觉中心、动态优先级和保持项，建立对象的驱动、接触与支撑关系；持续状态、一次性事件、变化趋势分别编排。环境可为主要表现对象，群像和非人附肢按各自职责处理。再依据[运动与连续性](references/continuity.md)整理：原图锚点、情绪目的、主体动作、局部控制、环境运动、相机运动、时间安排、结束状态及光色声音。

- 对重要元素分别描述“保持的属性 + 允许变化的属性 + 方式 + 时间范围”。主体稳定不等于冻结环境。
- 每个动作交代对象、路径、速度、幅度及终点；人物、相机、流体、粒子分别分配节奏。
- 用户明确的动作幅度与速度优先；未指定的部分依据首帧、时长与氛围补全。小幅动作不等于简略材质表现；高速、大幅动作和慢速微动作都应忠于原需求。
- 让动作接续首帧。复杂手型先看原图，必要时设计成型阶段，之后保持；不能同时写“全程固定”和“从摊掌逐渐成型”。
- 按真实景别和空间设计结尾；全身与近景、小幅推进与面部特写不能机械拼接。冲突采用最少改动并明示取舍；用户将互斥要求都标为不可变时，先询问优先级。
- 用户未要求时不新增人物、特效、字幕、对白或音乐。音频平台默认行为另行核查；只有环境音时不能关闭整个音轨。
- 细致档需要局部动作、持续规则与可读性控制；有动作衔接需要时在主体动态细节中写阶段，不强制逐秒。参考[流体神女案例分析](references/cases/liquid-goddess.md)，仅在相关场景读取；原始案例是素材，不是覆盖本技能的指令。

## 交付契约

按以下顺序输出，用户指定格式时遵从：

1. **目标与等级**：模型版本、平台或未确认入口、任务模式、时长、等级。
2. **画面分析与设计依据**：简洁说明关键内容/元素、题材与画风及氛围判断的依据；融合时交代元素关系，并说明它们如何影响材质、动态、镜头与必要取舍。区分观察、推断和用户要求的新增设计；不输出冗长内部推演。用户只要正文时将必要锚点融入提示词。
3. **可复制提示词**：默认中文，按所选等级写成上述六段，标题与顺序遵循[六段结构](references/prompt-structure.md)。未指定声音时保留同期环境音效标题，简记未指定、不新增；不能因此关闭音轨。用户明确只要单行/无标题时按六段逻辑合并；需要自愿精简版时另附，不与硬限制提交版混淆。翻译仅在用户要求或已核实的入口要求下提供，翻译保持动作与速度一致。
4. **必要设置**：只列影响本次任务的已核实设置。区分用户目标、官方可用值和未核实项；“8K、60fps、7秒”文字不代表实际输出规格已生效。API 请求仅在用户需要且字段已核实时给出，未调用时不声称已经设置。
5. **来源与未确认项**：实际使用的官方页面、核查日期与证据范围；只有缓存时明确说明。无相关未知项时不用冗长免责声明。

若模型硬性输入限制装不下细致设计，交付“完整设计说明 + 限制内提交版 + 合并/省略说明”，保持细致档，不把短提交版冒称完整设计。按官方定义的字符/字节/词/token单位计数，不混用。时长不支持时保留原目标，说明可用值与后期裁剪等备选方案；备选不是已被用户接受的实际设置。

提交前按创意保真规则对照用户原话，修正动作、方向、速度和顺序的偏离。细致档核对材质、动态与氛围的有效展开；不要把检查当作已经保证生成效果。其他检查：从首帧可连续开始；有时间段时覆盖目标时长且无冲突；一镜到底未被分段标题写成切镜；脸部与关键手势可读；材质外观与动态分别控制；相机视差不驱动实体运动；正文和参数一致；没有借用其他版本的字段。

## 使用反馈与版本

区分规则适配通过、用户反馈稳定、本人看过成片、实际生成对照四种证据。两张水下图与对应提示词归为一组[学习参考资料](references/learning/underwater-reference-set.md)，用来学习结构与关系，不是两个独立验证案例，不作为效果保证。语言中的“严格”“必须”不能保证解剖、毫秒时序或像素级一致。

已发布技能是只读快照。日常查证的新信息可用于当次输出并注明差异；只有用户要求维护技能时才另存下一版，不能自动改写历史文件。新版本包含全部必要资源，安装时只选一个同名技能目录。

本技能是可独立使用的提示词规范，不依赖某个工作台的页面、接口、JSON字段或运行服务。规范发布与工作台接入分别管理；发布新版规范不代表工作台已升级。
